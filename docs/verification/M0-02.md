## 1. 隔离原理

Godot 4.7 的 `--help` 中没有 `--user-data-dir` 一类参数（已核对实际输出），因此不能靠命令行开关改数据目录。

`user://` 由 `project.godot` 的 `application/config/name` 决定：`%APPDATA%\Godot\app_userdata\<name>`。

`tools/verify.ps1` 的做法：

1. 把项目复制到 `%TEMP%\life-verify-<id>\project`（排除 `.git`、`.godot`、`docs`）；
2. 把副本的 `config/name` 改写成 `LifeVerify-<id>`，并**校验改写确实生效**；
3. 运行 `--headless --stage=verify_smoke --fresh`，此时 `user://` 指向 `app_userdata\LifeVerify-<id>`；
4. 结束后删除临时项目与隔离存档，并**比对真实存档目录在运行前后的文件名/大小/mtime，确认未被触碰**；
5. 若隔离目录未被创建或真实目录发生变化，直接判失败并返回 2。

## 2. 断言入口

`--stage=verify_smoke` 是一个**行为断言**舞台，不是演示或截图：

| 断言 | 内容 |
|---|---|
| `isolated_user_dir` | `OS.get_user_data_dir()` 路径包含 `LifeVerify` |
| `origins_count` | `DB.origins.size() == 10` |
| `newborn_state` | 新开局 `age == 0` 且 `can_walk == false` |
| `save_roundtrip` | 写入 12345 → 改内存 → `_load_game()` 读回 12345 |
| `parents_present` | `pov_state` 同时存在 father 与 mother |

每条打印 `[VERIFY] PASS/FAIL <name>`，末尾打印 `[VERIFY] SUMMARY pass=N fail=M`，然后 `get_tree().quit(0/1)`。

## 3. 实际执行记录

```
$ godot --headless --path <temp>\project -- --stage=verify_smoke --fresh
[VERIFY] PASS isolated_user_dir C:/Users/Administrator/AppData/Roaming/Godot/app_userdata/LifeVerify-<id>
[VERIFY] PASS origins_count 10
[VERIFY] PASS newborn_state age=0 can_walk=false
[VERIFY] PASS save_roundtrip money=12345
[VERIFY] PASS parents_present
[VERIFY] SUMMARY pass=5 fail=0 failed=[]
process exit=0
```

`tools/verify.ps1` 汇总：

```
[verify] 断言 pass=5 fail=0  exit=0
[verify] PASS 真实存档目录未被触碰
脚本 exit=0
```

## 4. `--fresh` 防误删

原来 `--fresh` 无条件删除 4 个存档文件。现在只有在以下两个条件同时成立时才允许删除：

1. 环境变量 `LIFE_ALLOW_SAVE_WIPE=1`；
2. `OS.get_user_data_dir()` 含 `LifeVerify`（即隔离目录）。

独立复现（临时项目 + 预置一个存档文件，不带环境变量）：

```
godot --headless --path <temp>\project -- --stage=verify_smoke --fresh
WARNING: --fresh 被拒绝：需要在隔离数据目录下并设置 LIFE_ALLOW_SAVE_WIPE=1
存档是否还在：True
```
