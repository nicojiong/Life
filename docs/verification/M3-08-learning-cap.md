# M3-08 验证证据：识字上限统一（200），修掉"读书过 100 白读"

- 日期：2026-10-25
- 分支：`agent/m2-m3`
- 断言：64 → **65**

## 1. 问题

上一轮发现：`_apply_gain` 把识字钳在 **0–100**，但另外两处直接 `learning += N` 不钳，于是：

- 小孩识字能涨到 **109**；
- 可一旦超过 100，"读书 +3" 会被钳回去，**完全无效**；
- 上限到底是 100 还是 200，代码里没有唯一答案。

这是典型的"两条写路径、两套规则"。

## 2. 修法

| 改动 | 内容 |
|---|---|
| 新增常量 | `const LEARNING_CAP := 200.0` |
| 新增唯一入口 | `_add_learning(v)`：`clampf(learning + v, 0.0, LEARNING_CAP)` |
| 替换 7 处写识字 | 节令 +1/+2/+3、婴儿随机 +0~4、`_apply_gain`、旧档 +5、开局 +3 全部改为走 `_add_learning` |

现在识字只有一条写路径，上限 200，下限 0。

## 3. 断言

```
[VERIFY] PASS learning_cap_consistent at150=true cap=true gain_cap=true floor=true grows_past_100=true
[VERIFY] SUMMARY pass=65 fail=0 failed=[]
```

五件事：

1. 从 0 加 150 → 就是 150（不会被暗中钳到 100）；
2. 再加 100 → 停在 200；
3. `_apply_gain` 走同一上限（200 之后再加仍是 200）；
4. 负数不会掉到 0 以下；
5. **99 → 加 3 → 102**，即"读书过 100 之后仍然有用"。

## 4. 连带效果

求学路线长跑识字从 109 涨到 **200（上限）**，且仍然 `degree=true`：

```
[VERIFY] PASS m3_routes_walkable study=76/200.0 degree=true craft=64/2 care=62/true
```

其余 64 条断言（含长跑、档案、家庭、NPC）全部继续通过，没有回归。

## 5. 未覆盖

- 识字 200 之后没有新的内容门槛（比如"藏书/著述"），上限目前只是个数字。
- 科举概率 `0.10 + 识字×0.01` 在识字 90 时就封顶 0.90，200 与 90 没有区别——上限提高目前没有玩法收益。
- 手艺/医术/名望仍是旧的钳制写法，没有统一到类似的唯一入口。
