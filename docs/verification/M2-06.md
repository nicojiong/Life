# M2-06 验证证据：事实裁剪不再制造悬空引用

- 日期：2026-10-24
- 任务：M1-03 / M2-03 的遗留项
- 基线：`4bd793e`
- 存档版本：11 → **12**
- 断言总数：38 → **39**

## 1. 问题

`FACT_CAP = 240`：事实超过上限时从头部（最旧）丢弃。但因果链是靠 `cause_fid` 往回指的——被丢掉的那条如果还被引用，就变成了**悬空引用**。

18 年的人生已经有 78 条事实；按这个密度，一个活到 60 岁的人会把上限撞穿两三次。届时墓志的因果句会指到不存在的事实上。

## 2. 做法

裁剪时记录一个水位：

```gdscript
var fact_floor := 0   # 已被裁掉的最大 fid

while facts.size() > FACT_CAP:
    var dropped := facts.pop_front()
    fact_floor = maxi(fact_floor, int(dropped["fid"]))
```

`_fact_chain` 的终止条件从 `cursor != 0` 改成 `cursor > fact_floor`：

| 引用 | 判定 |
|---|---|
| `cause_fid <= fact_floor` | **已归档**，正常终止，不算悬空 |
| `cause_fid` 在 facts 里 | 正常回溯 |
| `cause_fid > fact_floor` 但找不到 | **真悬空**（数据损坏） |

`fact_floor` 入库（schema 12）。

## 3. 断言

```
[VERIFY] PASS fact_trim_archive floor=6 kept=240 oldest=7

```

连写 `FACT_CAP + 6` 条事实后检查：

| 检查 | 期望 |
|---|---|
| 保留条数 | 正好 240 |
| 被丢掉条数 | 6 |
| 水位 | 6 |
| 最旧仍在的 fid | 7 |
| 追一条**已被丢弃**的 fid | 返回空链（不崩、不算悬空） |
| 追最新一条 | 至少包含它自己 |

## 4. 未覆盖

- 只证明"裁剪后不悬空"，没有证明"长期人生里链仍然有意义"——被归档的事实内容已经没了。
- 没有墓碑清单，无法回答"第 3 条事实原本是什么"。
- 240 这个上限是写死的，没有按存档体积或人生长度自适应。
- 因果链最多回溯 16 层，长链条会被截断（目前链长 ≤ 3，还没遇到）。
