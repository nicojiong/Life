# M1-04b 验证证据：死亡与「缺字段」分离（A03）

- 日期：2026-10-24
- 任务：M1-04（切片 b），审计 A03
- 基线：`1788fe8`（M1-04a 分支）

## 1. 问题

`_parent_death()` 用「从 `pov_state` 删除父/母」表示死亡；`_load_game()` 看到缺少父/母，会按兼容旧档的逻辑**重新生成**一个。于是读档后死去的父母复活，玩家可以继续和他们说话。

同一个「字段缺失」状态同时表示了两件事：**已故** 与 **旧档没有这个字段**。

## 2. 修复

| 位置 | 改动 |
|---|---|
| 新增 `parent_dead` / `parent_death_year` | 显式死亡记录，人物实体保留 |
| `_parent_death()` | 标记死亡而不是删除 `pov_state` 条目 |
| `_spawn_npcs()` | 按 `parent_dead` 跳过，而不是按"条目是否存在" |
| `_refresh_pov_bar()` | 已故父母的按钮隐藏 |
| `_switch_pov()` | 已故父母不可切换 |
| `_load_game()` | 只在 `schema_version < 2`（旧档）时才补生成缺失的父母；新档不补，缺失即视为已故 |
| `_state_dict()` | 保存 `parent_dead`、`parent_death_year` |

## 3. 断言

```
[VERIFY] PASS save_roundtrip_full schema=2
[VERIFY] PASS dead_parent_stays_dead
[VERIFY] SUMMARY pass=11 fail=0 failed=[]
```

`dead_parent_stays_dead` 的流程：

1. 标记父亲已故、死亡年份 1050；
2. 存档；
3. 内存里把标记清成"活着"；
4. 读档；
5. 断言：`parent_dead.father == true`、`parent_death_year.father == 1050`、`_switch_pov("father")` 被拒绝（`pov` 仍是 `child`）、且 `pov_state` 里父亲记录仍在（可回望，不是删除）。

## 4. 未覆盖

- 旧档（schema < 2）仍会补生成父母：这是有意的迁移妥协，会打印但无法区分"当年就死了"与"字段缺失"。真正的迁移需要 fixtures，属 M1-04 剩余部分。
- 死亡后的人生回望（人生档案）未建立。
- 母亲的 `women_rank` 在父亲死亡后仍随 `pov` 切换正确保存，但未做"母亲单独去世"的对称用例。
