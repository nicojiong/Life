# M3-04 验证证据：人生档案

- 日期：2026-10-25
- 分支：`agent/m2-m3`
- 断言：60 → **61**

## 1. 档案包含什么

`_build_life_archive()` 在死亡时生成：

| 字段 | 内容 |
|---|---|
| 身份 | 姓名、乡里、生年、卒年、岁数、死因 |
| `chapters` | 最多 12 条，每条带 `fid`、年龄、年份、类别、人话 |
| `stats` | 钱、手艺等级、子女、婚否、田亩、官职 |
| `relations` | 态度最高的 3 位，带姓名 |
| `unfinished` | 未还债务、尚未执行的队列条数 |
| `verdict` | 评价，**显式标 `is_evaluation: true`**，与章回分开 |

章回覆盖的不只是官阶与财富：

| 类别 | 例子 |
|---|---|
| 营生 | 拜了师、出师了、开了作坊 |
| 家庭 | 成了家、添了孩子、把母亲的银簪当了、硬扛过病 |
| 人情 | 李婶来过 |
| 债务 | 借了米、还清了、欠着米没还 |
| 科举 | 解试中、解试落第 |
| 事件 | 遇上旱 |

## 2. 落盘与保留

写到 `user://life_archive_<slot>.json`，与普通存档分开——人生结束后普通存档会被清掉，档案单独留着，可以再读回来。

## 3. 断言

```
[VERIFY] PASS life_archive la_chapters=4 traceable=true ordinary=true separate=true roundtrip=true fresh=true
[VERIFY] SUMMARY pass=61 fail=0 failed=[]
```

六件：

1. 身份与生卒年有效；
2. **每条章回的 `fid` 都能在事实日志里找到**（可追溯，不是凭空写的词）；
3. 营生/家庭/人情/债务四类普通生活都出现（不只是官阶财富）；
4. `verdict` 标了 `is_evaluation`，且不混入章回；
5. 写盘后能读回，姓名一致；
6. 死亡后开新局：关系、债务、事件队列全空，`ended=false`（不继承旧局）。

## 4. 未覆盖与已知问题

- 档案只在 `_ending()` 里生成一次；「重复调用不重复写」目前靠 `if ended: return` 保证，断言里只做了静态检查，**没有真的调用两次来验证文件未被覆盖**。
- 章回去重按文本，同一句只会出现一次，可能把"多次借米"压成一条。
- `verdict` 仍是模板句，不是根据一生事实组合出来的评价。
- 档案没有在游戏内展示（只在死亡结算时生成文件），玩家目前看不到它。
