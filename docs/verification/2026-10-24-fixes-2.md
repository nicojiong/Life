## 1. 统一死亡入口

### 问题

死亡有四条入口，各自为政：

| 入口 | 原行为 |
|---|---|
| 时间推进 | `_trigger_actor_end()`：视角是父母时走 `_parent_death` |
| 战死 | `_die_young()` 直接 `_ending()` ——**不管当前操控谁，整局结束** |
| 行动/对话效果 | 走 `_apply_special` → 可能调 `_die_young()` |
| 事件效果 | 只扣健康，不判死 |

于是"替父亲出征战死"会把整局结束掉，而不是"父亲死了，孩子继续过"。

### 修复

```gdscript
func _kill_current_actor(cause: String) -> void:
    if ended: return
    death_cause = cause
    if pov == "child":
        _ending()        # 孩子死 = 这一局结束
    else:
        _parent_death()  # 父母死 = 登记在本人名下，孩子继续

func _trigger_actor_end(): _kill_current_actor("寿终")
func _die_young():         health = 0; lifespan = age; _kill_current_actor("战死")
```

### 断言

```
[VERIFY] PASS death_unified cause=战死 child_ended=true
```

三段：父亲视角战死 → 父亲已登记、`ended=false`、视角回到孩子；母亲视角寿终 → 同样只登记；孩子自己寿终 → `ended=true`。

## 2. 已安排事件按真实月份到期

### 问题

`_drain_due_events()` 只在"抽中一条新机会"时被调用。于是**排到下个月的事件可能永远不触发**——除非那年又抽中了新机会。

### 修复

`_advance_months` 每次 `month += 1` 后调用 `_drain_due_events()`。到期与抽选彻底解耦。

### 断言

```
[VERIFY] PASS event_due_by_month one=1 pending=1 two=1 cross=1 load=1
```

在 `events_enabled = false`（完全不抽新事件）下验证：

| 场景 | 期望 |
|---|---|
| 排 +1 月，推进 1 月 | 触发 |
| 排 +2 月，推进 1 月 | **仍挂起**（1 条） |
| 再推进 1 月 | 触发 |
| 12 月排 +2 月 | 跨年触发 |
| 存档 → 清空内存 → 读档 → 推进 3 月 | 恢复后仍按时触发 |
