# M1-05b 验证证据：年度边界的显式顺序

- 日期：2026-10-24
- 任务：M1-05（切片 b），审计 A04 / A06
- 基线：`79aaa7c`
- 断言总数：28 → **30**

## 1. 问题

年度结算是个几百行的大函数，各阶段靠"代码先后"隐式排序：

```
扣血 → 里程碑 → 年关 → 俸禄 → 弹劾 → 母亲收入 → 开科提示 → 随机事件 → 生子/抱孙
```

而**当前操控者的死亡判定**在 `_advance_months` 里、`_on_new_year()` 返回**之后**才做。

后果：一个已经到寿的人，仍然会走完年关扣钱、拿俸禄、碰随机事件、甚至触发生子里程碑——死了还在过年。

## 2. 修复

引入 `boundary_log`，把一年显式分成四个阶段，并**把死亡判定提前到结算之前**：

```
老化(aging) → 家人死亡(death) → 当前角色死亡(death_active) → 结算(settle) → 事件(events)
```

- 死亡在 `settle` 之前：死者不再扣年关、不再拿俸禄、不再遇事件；
- 每阶段的追加都带 `has()` 去重，同一年不会重复记录。

## 3. 断言

```
[VERIFY] PASS year_boundary_order ["aging", "death", "settle", "events"]
[VERIFY] PASS death_before_settle ["aging", "death_active"] money=10000
[VERIFY] SUMMARY pass=30 fail=0 failed=[]
```

| 断言 | 含义 |
|---|---|
| `year_boundary_order` | 健康的一年里，四个阶段齐全且 `settle` 在 `events` 之前；`aging` 必须是第一步 |
| `death_before_settle` | 到寿的一年里，日志只有 `aging`、`death_active`，钱**一分没扣**（10000 保持不变），且 `ended=true` |

第二条是关键：修复前，同样的场景会先扣一笔年关（约 1000 文）再去死。

## 4. 未覆盖

- 阶段顺序是写死在函数里的，不是由队列/调度器驱动；将来接事件调度器（M2）时需要再改一次。
- `boundary_log` 只保留最近一年，没有历史；跨年顺序没有断言。
- 家人死亡仍在 `aging` 阶段内处理，没有独立阶段标记的强制顺序（只做去重）。
- 尚未覆盖"保存中断长行动后恢复不重复扣费"（M1-05 剩余项）。
