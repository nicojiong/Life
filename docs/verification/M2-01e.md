# M2-01e 验证证据：事件致死的当月收尾

- 日期：2026-10-24
- 基线：`e93239c`
- 断言总数：49 → **50**
- 先写用例跑红（`in_month=false stopped=false one_event=false`），再修到绿

## 1. 当前人物的事件效果不判死

`_apply_event_to_inactive` 末尾会调 `_check_actor_deaths()`，但 `_apply_event_to_actor` 的"当前人物"分支只调 `_apply_event(id)` 就返回了。

于是孩子健康 1、次月旱灾到期后：`health` 变成 0，`ended` 仍是 false，要等到**下一次** `_advance_months` 开头的死活检查才结束。

修复：

```gdscript
func _apply_event_to_actor(who: String, id: String) -> void:
    if who == pov:
        _apply_event(id)
        _check_actor_deaths()   # 本次结算就判死
        return
    _apply_event_to_inactive(who, id)
```

## 2. 本局结束后仍继续执行同月事件

`_drain_due_events` 遍历所有到期实例，**从不检查 `ended`**。复现里的结果：

| | 修复前 | 修复后 |
|---|---|---|
| 孩子旱灾 −700 致死 | 触发 | 触发 |
| 母亲 reward +1200 | **仍触发** | 不触发 |
| 最终 money | 1500 | **300** |
| 记为"已发生事件" | 2 条 | 1 条 |

修复两点：

1. `_drain_due_events` 应用完一条后若 `ended`，先统计剩余未触发数量、写一条 `game_over/queue_frozen` 事实，然后 `break`；
2. `_advance_months` 在每月 `_drain_due_events()` 之后加 `if ended: return`，不再继续走年关与当月后续逻辑。

**未执行事件的策略**：留在队列里冻结，不触发、不记为发生；`game_over/queue_frozen` 记录剩余条数。本局结束后 `_save_game` 本来就会拒绝写盘，所以冻结队列不会进入存档。

## 3. 断言

```
[VERIFY] PASS event_kill_stops_month in_month=true money=300
[VERIFY] SUMMARY pass=50 fail=0 failed=[]
```

两段：

| 段 | 场景 | 期望 |
|---|---|---|
| in_month | 孩子健康 1，旱灾排次月，视角是孩子，`_advance_months(1)` | 这一个月结束时 `ended=true` |
| stopped | 视角是父亲，money 1000，孩子健康 1；同月先排孩子的旱灾，再排母亲的 reward | `ended=true`、`money==300`、`event` 事实只有 1 条（reward 未执行也未记录） |

两条都走正常的 `_advance_months` 路径，没有手动调判死器。

## 4. 顺带修的测试污染

新增的"当前人物事件后判死"会让**残留状态**里的父亲在无关用例中当场死亡（`event_actor_binding` 的 `father_untouched` 变红、`household_cost` 从 794 变 290）。

修法是在该用例里先把父亲的 `actor_vitals` 规范成 `34 岁 / 70 血 / 80 寿`，再切视角核对——**用例必须自带起点，不能继承前一个用例的状态**。

- 只有单月多事件的中止用例，没有跨月队列的中止用例。
