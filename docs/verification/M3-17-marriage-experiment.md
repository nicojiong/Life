# M3-17 验证记录：一次被数据否决的假设（婚育扩大覆盖）

- 日期：2026-10-25
- 分支：`agent/m2-m3`
- 结果：**假设被否决，改动已回滚**
- 断言：仍 73 条全过（回滚后本地复跑确认）

## 1. 假设

上一轮内容覆盖只有 **17/41（41%）**，缺口里有 4 条需要婚育（`spouse_ill`、`child_fever`、`grandchild_visit`、`wedding`）。

当时求学与手艺路线根本不结婚（只有照护路线在 20 岁成家），所以我推断：

> 让求学/手艺路线也在 24 岁后成家，就能解锁这几条婚育事件，覆盖率会上升。

## 2. 做法

在 `_route_step()` 的 `match route:` 之前加：

```gdscript
if route != "care" and not married and age >= 24 and money >= 400:
    _route_marry()
    return
```

## 3. 结果：覆盖率下降了

```
改前：covered=17/41  ratio=0.41
改后：covered=16/41  ratio=0.39
缺失列表变成 25 条，且新增了 wedding / widowed / old_friend_gone
```

原因不难理解：结婚那一年占用了一整年的行动机会，改变了随机流走向；而婚育事件本身的冷却（48–200 个月）和 `cond: parent`（需要先有孩子）决定它们一条命最多出现一次。**加一条成家路径并不等于加一次机会**。

## 4. 处理

按要求"不能靠降低门槛让测试变绿"，我把改动**整体回滚**：

- `git checkout -- scripts/street/village_scene.gd`
- 本地复跑：`pass=73 fail=0`，`content_reachability covered=17/41 ratio=0.41`

断言门槛仍是 **≥40%**，记录的是现状，不是合格线。

## 5. 这一轮真正的产出

1. 确认了 `8d5ccb3` 的 CI：`isolated-smoke=success`、`continuity=success`（上一轮因 API 403 未确认的那一半）。
2. 用一个可复现的实验否掉了一个听起来合理的假设，并留下数据（41% → 39%）。
3. 明确下一步方向：覆盖率瓶颈不在"路线结不结婚"，而在**抽选概率与冷却**——每年 32% 的抽选率、加上 12–200 个月的冷却，注定一条命只能碰十几条。
