# M1-03c 验证证据：墓志引用事实

- 日期：2026-10-24
- 任务：M1-03（切片 c），审计 A10
- 基线：`1bc41ac`（M1-03b 分支）

## 1. 问题

墓志此前完全由**当前字段**拼成：籍贯、职业等级、婚育、卒年。它能说"他是匠人"，说不了"他考了两次才中"；能说"终身未娶"，说不了"他为什么没娶"。

审计 A10 的判词是「普通、独身人生容易得到『余无可书』」。原因之一就是：**墓志没有可书的事**，只有可填的槽。

## 2. 做法

新增 `_facts_trace()`，把事实日志聚合成一句人话，插在子女之后：

```gdscript
func _facts_trace() -> String:
    if facts.is_empty(): return ""
    # 按 kind 计数 → 应试N次 / 逢变故N次 / 成家一次 / 送亲N人
    return "一生所记：" + parts + "。"
```

- 只有日志里真的发生过才写；`facts` 为空时**不写这一行**，不留空壳。
- 用词是"记"，不是"做"——因为它记录的是**系统认定发生过的事**，不是玩家的主观叙述。

## 3. 断言

```
[VERIFY] PASS epitaph_uses_facts 一生所记：应试2次、逢变故1次。
[VERIFY] SUMMARY pass=19 fail=0 failed=[]
```

三段校验：

1. `facts` 为空时 `_facts_trace()` 返回空串（**不留空壳行**）；
2. 写入 2 条 exam + 1 条 event 后，聚合结果含「应试2次」；
3. `_epitaph()` 的返回里**确实出现**以「一生所记」开头的一行——不是只有函数返回，而是真的进了墓志。

## 4. 未覆盖

- 墓志仍不读日志的**细节**（哪一年、中了什么），只读计数。
- 「余无可书」只被部分缓解：真正什么都没做的人生，日志为空，墓志里依然没有这一行。要解决需要"平凡生活也有事实可记"（种地、养大孩子、送走父母），那是内容层。
- 事实没有 `cause_ids` 链，无法写"因为欠债所以没娶"这类因果句。
- 控制台里这行中文显示为乱码，是 Windows 控制台 GBK 编码所致，不是数据问题（存档内是正确 UTF-8）。
