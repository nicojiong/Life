# M3-01 验证证据：事件定义搬进数据文件

- 日期：2026-10-24
- 任务：M3-01（切片 a）
- 基线：`2a95eb1`
- 断言总数：40（沿用，不新增）

## 1. 问题

`village_scene.gd` 已经 6000 多行，事件、节令、童年文案全在代码里。M3 要加大量内容，每加一条事件就要改这个巨型脚本——改错一个字符整个游戏起不来。

## 2. 做法

事件定义搬到 `data/events.json`：

```json
{"id": "drought", "name": "旱", "min_age": 8, "weight": 3, "cooldown": 60}
```

- `DB` 加载：`events = _load_json("res://data/events.json")`，启动打印条数；
- `village_scene` 的 `const EVENTS := [...]` 换成 `var EVENTS: Array = []`，在 `_ready` 里 `EVENTS = DB.events`；
- 文件缺失/为空时 `push_warning`，并且 `_content_issues()` 报 `events_missing`——**空列表不能静默通过**。

数值效果（扣多少钱、加多少健康）仍留在代码的 `match` 分支里；这一片只搬"定义"。

## 3. 证明数据文件真的生效

改了 JSON 就等于改游戏——这件事必须验证，不能只看断言绿。

在 `events.json` 里临时加一条「庙会」，重跑：

```
[DB] 出身 10 种，年号 20 个，事件 15 条
[VERIFY] PASS content_ids_valid events=15 scenes=6
[VERIFY] PASS opportunity_cooldown fresh=10 cold=9 warm=10
```

候选池从 9 变 10，事件数从 14 变 15，**不碰任何代码**。随后撤回注入，恢复 14 条、全部断言通过。

## 4. 顺带补的一个洞

`_content_issues()` 原本遍历 `EVENTS`，如果 `EVENTS` 是空数组，遍历零次 → **没有问题** → 断言通过。

也就是说：`events.json` 丢了，游戏没有年度事件，测试全绿。现在加了 `events_missing`，空列表会被抓。

## 5. 未覆盖

- 效果仍在代码里，加一条**有独特效果**的事件仍要改 `_apply_event`。
- 文案（toast 文本）仍在代码里，没搬进 JSON。
- 没有 schema 校验（字段拼错只是取不到默认值，不会报错）。
- 老存档没有"事件定义版本"概念，改权重/冷却会影响进行中的存档。
