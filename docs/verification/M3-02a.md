# M3-02 验证证据：事件效果与文案数据化

- 日期：2026-10-24
- 任务：M3-02（切片 a）

## 1. 问题

M3-01 只把"定义"（id/年龄/权重/冷却）搬进了 JSON。效果和文案还在 `_apply_event` 的 `match` 里——加一条有独特效果的事件，仍然要改 6000 行的脚本。

## 2. 做法

`data/events.json` 每条事件增加 `text` 与 `effects`：

```json
{
  "id": "drought", "name": "旱", "min_age": 8, "weight": 3, "cooldown": 60,
  "text": "春旱，河断了流。粮价涨了三成，家里先紧着吃。",
  "effects": {"money": -700, "health": -3}
}
```

`_apply_event` 分两条路：

| 条件 | 路径 |
|---|---|
| 定义里有 `effects` | `_apply_event_effects()` 通用结算（money/health/fame/story + 文案） |
| 没有 `effects` | 仍走代码分支（`plague` 按 `med_rank` 分档、`harvest` 按田亩算收益） |

颜色也由数据决定：钱/健康/声望有任一项为负 → 冷色，否则暖色。

## 3. 断言

```
[VERIFY] PASS event_effects_from_data temple=+30 riverfall_story=true
[VERIFY] SUMMARY pass=41 fail=0 failed=[]
```

四段：

1. 新事件 **「庙会」只在 JSON 里定义**（代码里没有任何庙会分支）→ 钱 +30；
2. 同一条事件的声望 +2；
3. 「落水」的 `story: "落水"` 被写入；
4. 「旱」扣 700 文（现金不足时截到 0，所以断言接受 330 或 300）。

第 1 条是关键：**它证明"加内容不用改代码"这件事真的成立**，而不只是把字段挪了个地方。

## 4. 未覆盖

- `plague`（按医者等级分档）与 `harvest`（按田亩算收益）仍在代码里，是有意保留的"需要计算"的事件。
- `_apply_event` 里那 13 条已被数据接管的旧分支还在，成了**死代码**——留着会误导后来的人，应该删掉（下一轮）。
- 没有 schema 校验：JSON 里把 `"money"` 写成 `"cash"` 只会静默不生效。
- 文案仍是单句，没有按家境/年龄换措辞（节令文案有 `poor` 变体，事件还没有）。
