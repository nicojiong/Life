# M1-02b 验证证据：年关只结算一次

- 日期：2026-10-24
- 任务：M1-02（切片 b），审计 A04 / A06
- 基线：`76766e7`（M1-02a 分支）

## 1. 问题

`_on_new_year()` 是个没有水位守卫的大函数：老化扣血、里程碑、年关收支、俸禄、弹劾、随机事件全在里面。只要它被调用两次，玩家就会**被扣两次年关、掉两次血、过两次节令清理**。

它现在的调用路径只有 `_advance_months` 的年翻页，但：

- `_advance_months(n)` 在一次行动里可能连续跨多年（比如 24 个月）；
- 里程碑会开过场（`busy=true`），期间若发生嵌套推进，函数可能重入；
- 未来接事件队列后，年关会由调度器触发，不再只有一条路径。

所以先把"一年只结算一次"写成硬约束。

## 2. 修复

```gdscript
func _on_new_year() -> void:
    if last_settled_year >= year:
        print("[YEAR] settle_skipped year=", year, " last=", last_settled_year)
        return
    last_settled_year = year
    ...
```

`last_settled_year` 入库（schema 3 追加字段，旧档按默认 `0` 处理，等价于"从未结算"，不会跳过真实年关）。

## 3. 断言

```
[YEAR] settle_skipped year=1046 last=1046
[VERIFY] PASS new_year_settles_once deducted=854
[VERIFY] SUMMARY pass=15 fail=0 failed=[]
```

流程：`age=30`、`money=10000`、`last_settled_year=year-1` → 调一次 → 记下余额 → 再调一次。

- 第一次扣 **854 文**（300 + 30×4 + 婚配 200 + 子 180 + 田 3×18），与公式一致；
- 第二次打印 `settle_skipped`，余额不变。

## 4. 这一条为什么值得单独做

年关是玩家唯一**每年必然**的钱与健康变化来源。它一旦重复结算，"我明明还有钱"和"我明明没生过病"这类不可复现的异常就会混进存档，后面所有经济与寿命的验收都会失真。

水位守卫是廉价的，但它把"年关每年到底发生几次"从"取决于调用路径"变成"由数据说了算"。
