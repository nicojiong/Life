# M3-15 验证证据：41 条真实事件的年龄边界逐条核对

- 日期：2026-10-25
- 分支：`agent/m2-m3`
- 断言：71 → **72**

## 1. 从"合成事件"换成真实数据

上一轮的年龄边界只用一个编造的事件验，等于只测了函数、没测数据。这轮直接扫 `data/events.json` 里全部 **41 条**。

每条事件的四个位置都要对：

| 位置 | 期望 |
|---|---|
| `min_age - 1` | 不成立（进不来） |
| `min_age` | 成立（边界算在内） |
| `max_age` | 成立 |
| `max_age + 1` | 不成立（已出界） |

为了只测年龄、不被 `cond`（贫/富/官/匠等条件）干扰，每条都先 `duplicate()` 再 `erase("cond")`。

## 2. 断言

```
[VERIFY] PASS event_age_boundaries events=41 bad=0 action_max_age=true
[VERIFY] SUMMARY pass=72 fail=0 failed=[]
```

- `events=41`：一条不漏
- `bad=0`：没有"进不来 / 出不去"的错误边界
- `action_max_age=true`：动作侧也有了真实上限

## 3. 动作侧补上真的上限

给"应解试"加 `max_age: 42`（面板与路线两处），并在断言里验证：

- **43 岁**点应解试 → 钱不变（被挡）
- **30 岁**点同一条 → 钱被扣（放行）

这样 `max_age` 不再只是代码里一行没人用的参数。

## 4. 未覆盖

- 只扫了边界四个点，没有验证"同一条事件在边界内多次出现时的冷却与权重"。
- 删掉 `cond` 后测的是纯年龄门，**带条件的事件在真实处境下是否可达没验**（例如"求学"事件需要 `story["读书"]`）。
- `max_age` 只在应解试一条动作上生效，其余动作仍未使用上限。
