# M2-01d 验证证据：死亡结算收尾（条件 vs 已结算）

- 日期：2026-10-24
- 基线：`db41293`
- 断言总数：48 → **49**
- 先写用例、跑红（`killed=false aged=false`），再修到绿

## 1. "达到死亡条件"与"已经结算"混为一谈

### 问题

`_actor_is_dead("child")` 在健康 ≤ 0 时就返回 `true`。而 `_check_actor_deaths()` 的第一步是 `if _actor_is_dead: continue`——于是孩子健康归零后：

- 死亡检查跳过它；
- `_settle_actor_death` 也在入口 `if _actor_is_dead: return` 直接返回。

结果：**孩子永远 `ended=false`**，一个"活着但不该活着"的人还能接住后续 `transfer`。

### 修复

拆成两个概念：

| 函数 | 含义 |
|---|---|
| `_actor_can_die(who)` | 达到死亡条件：健康 ≤ 0 或年龄 ≥ 寿数 |
| `_actor_is_dead(who)` | **已经完成结算**：孩子看 `ended`，父母看 `parent_dead` |

`_check_actor_deaths()` 改用 `_actor_can_die` 触发；转移的可用性判断同时要求"没死"且"没有达到死亡条件"。

## 2. 年边界接通所有人的死亡检查

新增 `_kin_death_pass()`：年边界老化后，对**不在当前视角**的家人（父/母/孩子）统一判死；当前视角的死亡仍按原来的 `death_active` 分支在结算之前处理（保持 `death_before_settle` 的语义）。

删掉了原来内联的"父母死亡标记"和上一轮补的"孩子健康归零特判"——它们都被这一个入口取代。

## 3. 转移事实保留原主体、实际承受者与结果

```
{"kind": "event", "data": {"id": "drought", "sid": 1,
                           "from": "father", "to": "child", "result": "transferred"}}
```

取消事件仍写成 `event_cancelled_dead_target` / `event_cancelled_unknown_target`，不进 `event` 统计、不进墓志。

## 4. 断言

```
[VERIFY] PASS death_settlement killed=true aged=true kin=true transfer=true refuse=true
[VERIFY] SUMMARY pass=49 fail=0 failed=[]
```

| 段 | 场景 | 验证点 |
|---|---|---|
| killed | 操控父亲，孩子被事件扣到 0 | `ended=true`，进入孩子结局 |
| aged | 操控父亲，孩子 59 岁、寿数 60，走 `_advance_months(12)` | 正常年关结束后 `ended=true`；**没有手动调用判死器** |
| kin | 父母同年到寿 | 两人各登记一次、`parents_alive` 从 2 减到 0、孩子继续 |
| transfer | 父亲已故、孩子活着 | 转移成功：孩子掉血，事实里 `from=father / to=child / result=transferred` |
| refuse | 父亲已故、孩子也已死 | 转移被拒：钱与孩子健康都不变，无 `event_transferred` |

## 5. 同时修正的旧用例

`event_boundaries` 里的 transfer 段原来把事件排给**活着的**父亲，只断言"没有写入 `event_transferred`"——那不能证明拒绝。现在改成：孩子已死 + 父亲已故 → 要求转移，断言**资源不变且无转移事实**。

## 6. 未覆盖

- `_kin_death_pass` 与 `_check_actor_deaths` 两条路径仍有重叠（前者带年边界日志，后者不带），没有合并成一个带上下文的接口。
- 父母同年去世时只验证了计数，没有验证两句讣告/两次事实。
- 转移没有多跳（父亲→孩子失败后不会转给母亲）。
- 死亡后的人生档案仍未建立，`death_cause` 仍是单值覆盖。
