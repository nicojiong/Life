## 2. 新增机制

| 名称 | 行为 |
|---|---|
| `_family_year_tick()` | 年边界：提亲判定 + 添丁判定 |
| 「提亲」场景（五月，`cond: marriage`） | 应下 / 再等两年 / 回掉这门亲 |
| `_marry_accept()` | 成家、扣 200 文、留事实 |
| `_marry_defer()` | 两年后再提 |
| `_marry_refuse()` | `story["拒婚"]`，此后不再提，日子照过 |

**添丁用确定性节奏**（`(year + age) % 3 == 0`）而不是随机数——`_arnd()` 会消耗模拟随机流，导致黄金重放与续跑对不齐（本轮实际踩到）。

## 4. 本轮踩到的坑

- 黄金重放直接变红：`_family_year_tick()` 用 `_arnd()` 掷骰子，重放第二次运行 RNG 位置不同，学习值 35 vs 37、事实 2 vs 1。改成确定性节奏后恢复。
- 三次把新变量名撞进已有作用域（`child_ok`/`refuse_ok`/`orphan_not_forced`），全部靠编译器逐条清掉。

## 6. 已修复：重放确定性（自动触发恢复）

提交 `03fdf23` 在 Linux CI 上 `golden_replay` 变红（本地是绿的），差异是重放第二次多跑出一年：
`a=story0/hp78` vs `b=story1/hp77`。

试过三种修法都无效：把提亲/添丁改成确定性节奏、去掉重放里漏掉的 `marriage_*` 恢复、补 RNG 与 `month_frac` 恢复。

根因：`_replay_snapshot()` 只存了 `marriage_*`，**没存 `married / children / milestones / heirlooms / 债务 / 学徒状态 / scenes_done`**。家庭 tick 一改变这些值，重放第二次就从不同的中点起跑，于是多跑出一年。

修法：把上述字段全部纳入重放快照与还原（只用 `snap.get(..., 当前值)` 兜底，不改业务语义），然后恢复挂载：
- 年边界重新调用 `_family_year_tick()`
- `YEAR_SCENES` 重新加入「提亲」

本地 60 条全过，CI（Linux）为最终判据。
