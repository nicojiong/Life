# M2-02 验证证据：机会调度与冷却

- 日期：2026-10-24
- 任务：M2-02（切片 a）
- 基线：`18f28e8`
- 存档版本：9 → **10**
- 断言总数：33 → **34**

## 1. 问题

上一版年度事件还是"32% 概率从候选里**均匀**抽一条"：

```gdscript
if _rnd() > 0.32: return
var ev := _pick_from(pool)   # 每个候选概率相同
```

两个后果：

- **没有轻重**：瘟疫和水灾一样容易抽到；
- **没有记忆**：连续三年旱灾是可能的，读起来像 bug。

## 2. 做法

事件定义加两个字段：

```gdscript
{"id": "drought", "min_age": 8, "weight": 3, "cooldown": 60}
```

调度分三步：

| 步骤 | 作用 |
|---|---|
| `_eligible_opportunities()` | 过滤：年龄/条件满足 **且** 冷却已过（`now - opp_last[id] >= cooldown`） |
| `_weighted_pick(pool)` | 按 `weight` 加权抽取，而不是均匀 |
| `_enqueue_event(id, "opportunity", now + _rndi(0, 2))` | 入队，1–3 个月内到期（不再是抽到即结算） |

`opp_last`（id → 上次安排月份）随存档保存，schema 10。

## 3. 断言

```
[VERIFY] PASS opportunity_cooldown fresh=9 cold=8 warm=9
[VERIFY] SUMMARY pass=34 fail=0 failed=[]
```

三段对比：

| 场景 | 候选数 | 含义 |
|---|---|---|
| 无记录 | 9 | 基线 |
| 刚安排过（`opp_last = 现在`） | 8 | **正好少一条**，且少的必须是 drought |
| 5 年前安排过（`opp_last = 现在 - 120`） | 9 | 冷却已过，重新进池 |

断言不只比数量，还逐项确认 drought 在/不在池里。

## 4. 未覆盖

- 调度仍是"每年一次、32% 触发"的节拍，没有按事件各自的节日/季节窗口；
- 没有互斥（例如同一年既旱又涝），也没有"排队上限内按优先级插队"；
- `opp_last` 只记安排时间，不记"实际发生"时间；
- 权重是手调的常数，没有从内容数据读；
- 没有断言"加权抽取的分布符合权重"（需要大样本统计，成本高）。
