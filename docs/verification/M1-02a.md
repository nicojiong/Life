# M1-02a 验证证据：统一结算入口与行动冷却

- 日期：2026-10-24
- 任务：M1-02（切片 a），审计 A04
- 基线：`2fa4a31`（M1-04d 分支）

## 1. 问题的真实形态

审计说「短行动可以即时刷值」，具体是：

| 路径 | 时间处理 |
|---|---|
| 地点行动 | 只有 `months >= 6` 才推进；`歇三个月`、`看告示`、母亲`浆洗三个月` 全部**即时结算** |
| 对话选项 | 无条件 `_advance_months(months)`——同样的事走对话要花时间，走地点却免费 |
| 节令 | 自己 `_advance_months` |
| 实时钟 | 独立推进 |

于是同一件"干活"，从面板点不花时间、从对话点花一个月；而面板那条可以无限连点。

## 2. 本切片的取舍

用户明确要求「**做动作不消耗时间，时间自己走**」，这与审计的「收益动作必须付出时间」表面冲突。

取舍：**时间仍然不花，但同一件事在冷却期内不能重复**。冷却长度 = 该行动声明的 `months`。

- 长行动（≥6 月）本身就把时间推过去了，冷却从推进之后开始算——连做两次仍然是 12 个月换两次收益，没有额外惩罚。
- 短行动（1–3 月）不推进时间，冷却按声明月数挡住连点。

这样"做事不花时间"这条设计保住了，"连点刷钱"这条路堵上了。

## 3. 实现

| 位置 | 改动 |
|---|---|
| `_cooldown_ready(label)` | 检查是否还在冷却；拒绝时提示「这事刚做过，再过 N 个月」 |
| `_cooldown_commit(label, months)` | 结算完成后记录 `_month_index() + months` |
| `_on_action` | 扣钱/关面板**之前**检查；收益结算**之后**提交 |
| `_on_dialog_choice` | 同样检查与提交；**删除**它原先的 `_advance_months` |
| 存档 | `action_cooldown` 入库，`SAVE_SCHEMA_VERSION` 升到 3 |

对话不再推进月份，与地点行动统一：两条路径现在共用同一套结算。

## 4. 断言

```
[VERIFY] PASS action_cooldown_blocks_spam money=800
[VERIFY] SUMMARY pass=14 fail=0 failed=[]
```

流程：`money=500`，执行一个 `months=1 / +300` 的行动两次。第一次 800，第二次被拒绝仍是 800。

## 5. 两次测错，两次都是我的模型写错

1. **第一版**用 `months=6` 的行动测，结果第二次仍然发奖。原因：行动自己把时间推了 6 个月，冷却也正好是 6 个月，检查时刚好到期——**长行动根本不需要冷却，它已经付过时间了**。改成用 `months=1` 的短行动才测出真实缺口。
2. **第二版**断言绝对值 `800`，实际拿到 `300`。原因是上一条测试把年龄留在了 21 岁，6 个月推进跨年触发了年关结算，钱被扣走。改成先 `age=5` 再做这条断言。

这两次都不是"实现有 bug"，而是**断言本身没有隔离住它要测的东西**。

## 6. 未覆盖

- 没有测「冷却过后可以再做」的正向路径（需要推进世界钟，属长时间模拟）。
- 节令场景自带的时间跳转未纳入统一结算，仍是独立路径。
- `_month_index()` 用 `year*12+month`，跨年边界未单独验证。
