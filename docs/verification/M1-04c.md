# M1-04c 验证证据：原子写入与备份回退

- 日期：2026-10-24
- 任务：M1-04（切片 c），审计 A02
- 基线：`f019e8d`（M1-04b 分支）

## 1. 问题

`_save_game()` 直接 `FileAccess.open(path, WRITE)` 覆盖主文件。写到一半断电/崩溃会留下半截 JSON，读档时 `JSON.parse_string` 失败，**整档报废**，且没有任何备份可退。

## 2. 修复

```
写 tmp → 旧 main 改名成 bak → tmp 顶替 main
```

| 步骤 | 命令 | 断电后果 |
|---|---|---|
| 1 | 写 `fusheng_save_1.json.tmp` | main 仍是上一版，可用 |
| 2 | `main` → `.bak`（覆盖旧 bak） | main 短暂不存在，bak 是上一版 |
| 3 | `.tmp` → `main` | 新档就位，bak 仍是上一版 |

读档时：主文件解析失败或不存在 → 读 `.bak`，成功则置 `recovered_from_backup` 并打印 `[SAVE] recovered_from_backup`。

`_clear_save()` 现在同时清理 `main`、`.bak`、`.tmp`。

## 3. 断言

```
[SAVE] corrupt_or_unreadable user://fusheng_save_1.json err=Expected key
[SAVE] recovered_from_backup
[VERIFY] PASS save_recovers_from_backup money=100
[VERIFY] SUMMARY pass=12 fail=0 failed=[]
```

`save_recovers_from_backup` 的流程：

1. `money=100` 存档；
2. `money=200` 再存（此时 `.bak` = 100 那版）；
3. 把主文件写成 `{ this is not json`；
4. `money=0`，读档；
5. 断言：读档成功、`recovered_from_backup == true`、`money == 100`。

## 4. 顺带修掉的日志噪声

第一版用 `JSON.parse_string()`，损坏时会往 stderr 打一行引擎 `ERROR: Parse JSON failed`。改成 `JSON.new().parse()` 后，损坏只由我们自己的 `[SAVE] corrupt_or_unreadable ... err=...` 报告——**真错误留在日志里，预期的损坏不再伪装成引擎错误**。
