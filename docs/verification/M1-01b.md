# M1-01b 验证证据：生命值收拢到 actor 表

- 日期：2026-10-24
- 任务：M1-01（切片 b），审计 A05 / A06
- 基线：`c416cc5`
- 存档版本：7 → **8**
- 断言总数：30 → **31**

## 1. 问题

年龄/健康/寿数在**两个地方**都有副本：

- 当前操控者的：全局 `age` / `health` / `lifespan`；
- 其他人的：`pov_state[id]` 里同名字段。

`_capture_pov()` 与 `_apply_pov()` 靠 `POV_FIELDS` 在两个副本之间搬。谁多写一处、谁漏读一处，就是"切个视角人变了"。

## 2. 收拢方式

新增 `actor_vitals`（id → `{age, health, lifespan}`）：

| 角色 | 真值在哪 |
|---|---|
| 当前操控者 | 全局字段（性能与改动面最小） |
| 其余人 | `actor_vitals[id]` |
| `pov_state[id]` | **只剩职业与 story**，不再存生命值 |

`POV_FIELDS` 里删掉 `age` / `health` / `lifespan`；`_capture_pov()` 先 `_store_active_vitals()` 写入 actor 表，`_apply_pov()` 只从 actor 表恢复。

同步点收敛为三处：换视角、年度老化、年度扣血/判死。

## 3. 过程中暴露的两个真 bug

1. **`_apply_pov` 读错了源**：它调用 `_vitals_of(pov)`，而此时 `pov` 已经切换成目标角色，函数走了"当前操控者 → 读全局字段"的分支，于是父亲继承的是孩子的血条。改成直接读 `actor_vitals[pov]`。
2. **目标角色没有职业快照时直接跳过应用**：`if not target.is_empty(): _apply_pov(target)`——切回孩子时若从未存过 `pov_state["child"]`，生命值就不会恢复。补了 `else: _apply_pov({})`，只按 actor 表恢复生命值。

这两个都是"以前靠 `pov_state` 里恰好有字段才没出事"，收拢之后才显形。

## 4. 断言

```

[VERIFY] SUMMARY pass=31 fail=0 failed=[]
```

流程：记下孩子当前真值 → 给父母写入 44/66/70 与 41/58/72 → 孩子 → 父亲 → 母亲 → 孩子，逐段核对每人的年龄/健康/寿数，最后确认父亲的记录没被切走时覆盖。

## 5. 未覆盖

- 当前操控者的真值仍是全局字段，`actor_vitals[pov]` 只是缓存；严格意义的"单一所有者"还差一步（把全局改成派生属性）。
- `pov_state` 仍保留职业字段的副本，切换时靠 `_capture_pov` 搬。
- 存档迁移只做了"缺 actor_vitals 时从 pov_state 旧字段推导"，没有 v7 之前的专门 fixture。
- 家人死亡仍在年度结算内处理，没有独立的 actor 生命周期接口。
