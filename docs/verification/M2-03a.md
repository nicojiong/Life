# M2-03 验证证据：因果链（cause_ids）

- 日期：2026-10-24
- 任务：M2-03（切片 a）
- 基线：`6b0fd74`
- 存档版本：10 → **11**
- 断言总数：34 → **35**

## 1. 问题

事实日志里的 `cause` 只是一个字符串（`year_end`、`opportunity`、`old_age`）。它能说"这条事实属于哪一类"，不能回答"**这条事实是被哪一条事实引起的**"。

于是墓志只能写"逢变故 1 次"，写不出"因为那年旱，才卖了田"。

## 2. 做法

每条事实拿到自增 `fid`，并可选地指向造成它的上一条事实：

```gdscript
{"fid": 7, "t": 12552, "kind": "death", "cause": "old_age",
 "data": {...}, "cause_fid": 6}
```

链路目前接了三段真实关系：

| 事实 | cause_fid 指向 |
|---|---|
| 年关结算（`year/boundary`） | 0（一年的起点） |
| 年度事件（`event/opportunity`） | 当年的年关结算事实 |
| 父母过世（`death/old_age`） | 最近一次事件事实 |

`_fact_chain(fid)` 往回追，最多 16 层（防脏数据死循环）。

## 3. 断言

```
[VERIFY] PASS cause_chain_resolves [3, 2, 1] boundary=[1]
[VERIFY] SUMMARY pass=35 fail=0 failed=[]
```

检查四件事：

1. 链条长度正好 3：死亡 → 事件 → 年关；
2. 三段 id 与逐段记录的 fid 完全对应（不是"能追到就算过"）；
3. 年关事实的链只有它自己（`[1]`），说明根节点没有伪造父引用；
4. **全表扫描没有悬空引用**：任何 `cause_fid != 0` 都必须能在日志里找到对应 fid。

第 4 条是真正防腐化的：以后有人删了事实、截断了日志（`FACT_CAP` 会丢最旧的），链条就会断，这条断言会先叫。

## 4. 未覆盖

- 只有三条真实链路，`cause_fid` 在大多数事实里仍是 0。
- `FACT_CAP = 240` 会丢弃最旧事实，被丢弃者的 fid 会变成"悬空"——目前只在截断前成立，长期运行需要墓碑记录。
- `_fact_chain` 只往回追，不能向前查"这件事导致了什么"。
- 墓志还没有用链条写句子（仍是计数）。
