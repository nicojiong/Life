# M2-01 验证证据：事件定义与实例分离

- 日期：2026-10-24
- 任务：M2-01（切片 a）
- 基线：`6815b41`
- 存档版本：8 → **9**
- 断言总数：32 → **33**

## 1. 问题

事件只有"定义"没有"实例"：

```gdscript
const EVENTS := [{"id": "drought", "min_age": 8}, ...]
func _roll_event(): 抽一条 → _apply_event(id) 立刻生效
```

抽到即结算，没有到期时间、没有来源、没有可排队的对象。M2-02 要的"到期队列与机会调度"没有东西可排；M2-03 要的"因果样例"也没有可引用的实例 id。

## 2. 做法

**定义**（`EVENTS`）保持不变；新增**实例**：

```gdscript
var event_instances: Array = []   # {sid, id, cause, due, fired}
var event_seq := 0

_enqueue_event(id, cause, due_month) -> sid
_drain_due_events() -> int         # 到期才触发，每个实例只触发一次
```

- `_roll_event()` 现在只做两件事：抽定义 → 入队（`due = 当前月`）→ 立即 drain；
- 事实日志从 `_apply_event` 移到 drain，记录的 `cause` 就是实例的来源，`data` 里带实例 `sid`；
- 已触发实例从队列移除，队列上限 64 条；
- `event_instances` / `event_seq` 入库（schema 9），也纳入黄金重放快照。

## 3. 断言

```
[VERIFY] PASS event_instance_drained_once fired=1/0/1/0
[VERIFY] SUMMARY pass=33 fail=0 failed=[]
```

流程：

1. 入队一条「现在到期」、一条「3 个月后到期」；
2. 第一次 drain → 触发 1 条，队列剩 1 条；
3. 再 drain → 触发 0 条（已触发的不重复）；
4. 把未来那条的 `due` 改成现在 → drain → 触发 1 条；
5. 再 drain → 0 条，队列空，两个 `sid` 不相等。

## 4. 过程中打断的两处

1. **插入存档字段时切断了 `if/else`**：`event_instances` 的读档代码插在 `if actor_vitals ... else:` 中间，`else` 变成了孤儿，整个脚本编译失败。`--check-only` 直接指到 588 行。
2. **`facts_have_causes` 变红**：它原来直接调 `_apply_event("drought")` 来造事实，而事实已改由 drain 记录。改成走完整的入队→到期路径。这正是断言该抓的：行为的入口变了，测试也得跟着走真实路径。

## 5. 未覆盖

- 定义仍是 GDScript 常量，没有数据文件化（M2-01 的下一片）。
- 实例只有"到期月"，没有持续时间、权重、互斥、冷却（M2-02）。
- `cause` 还是字符串（`year_end`），不是别的实例的 `sid` —— 因果链要等 M2-03。
- 队列上限 64 且静默丢弃最旧的，没有"被丢弃"记录。
