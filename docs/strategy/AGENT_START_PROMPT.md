# 可直接发给开发 Agent 的启动指令

请在 https://github.com/nicojiong/Life 上按随附的《Life / 浮生战略规划与 Agent 执行包》实际推进开发。目标是：玩家先选时代，随机出生于一个个人世界，从依赖父母到逐渐拥有自主权，通过自己的行为、NPC的行为和合理偶然，形成有持续因果的人生，直到死亡和人生回望。出生决定起点，不能锁死终身职业；不读书、改行、离乡、留乡照护和普通生活都应有可行路径。

## 先读取与核实

读取当前仓库的 AGENTS.md（若存在）、README、docs/GDD.md、规划包 START_HERE.md、docs/strategy 全部文档、backlog.json 和 STATE.json。本规划审计基线是 2d035379f21abbc8d1d6f06d0328eb756751b993；先检查当前 HEAD 与基线的差异，以最新实际代码为准更新任务，不能照抄已失效结论。

本次规划未运行游戏、未实施代码修复、未提交push。所有31张开发任务初始都是todo。你需要执行工作，不要只复述规划或承诺未来会做。

## 本轮先做 M0-01

确认现状、有效规则、版本和环境，整理基线及源码/文档矛盾。先合并规划文件到仓库内的明确位置，并记录路径；保留现有文件身份与用户修改。不要立即新增时代、批量生成数百事件或重写整个主场景。

在未证实测试数据目录隔离前，仅做源码、Godot版本与编辑器导入检查；普通游戏启动也可能写真实存档，不能以“没加--fresh”为理由认为安全。实际启动验证在已有隔离条件下进行，或留到 M0-02 建立隔离入口后完成并明确记录。现有 --stage 是调试入口，截图和print不是自动测试。

## 每个任务必须形成闭环

1. 按依赖领取一个可验收任务，记录目标、范围、基线SHA、分支、预算、预期行为和回归风险。
2. 阅读实际实现并复现问题，采用小步渐进修改；复用现有 Godot、二维街景和可用机制。
3. 运行与改动有关的真实检查。涉及模拟时，验证统一时间、人物状态、因果、随机重放、存档和死亡边界；纯文档修正不制造无意义代码测试。
4. 做独立差异审阅；修正问题。失败测试不可删除或偷偷跳过来换取通过。
5. 更新任务卡与必要文档，逐文件暂存、commit、push到对应agent任务分支，核验远端SHA与本地HEAD一致。用户已要求每部分完成后push，不要仅保留本地代码。
6. 创建或更新同一任务的PR，核对最新commit的CI。无CI、pending、skipped、环境失败都按真实状态汇报，不能说全部通过。
7. 在报告中列出实际修改、验证证据、commit、remote SHA、PR、剩余问题和下一步。任务push后不等于已merge；只有约定集成完成才标done。

## 持续迭代与恢复

在执行预算允许、依赖满足且没有阻断时，自主继续下一项。预算默认建议每轮60分钟、付费API调用0次，可按现有明确授权调整；这是检查点边界，不是任务完成条件。先把M0–M3做通，再推进社会规模、内容生产和多时代。

没有自动合并授权时，交付可审阅PR。后续依赖任务可以基于前置任务已验收、已push的精确SHA创建堆叠分支，PR以该前置分支为base，记录集成顺序；前置任务不能因被依赖而提前标done。主分支保护、已有审批和付费权限照常遵守。

中断前把分支、base SHA、最新commit、远端SHA、已跑检查、失败原因、未完成部分与下一条具体动作写入STATE和任务卡。下一轮恢复同任务分支/PR，不重复建一套。网络或权限使push失败时，保留本地成果并如实记录blocked与恢复方法。

## 共同设计约束

- 世界只有一条模拟时间；表现动画可以独立平滑运行，不能改变经济、年龄或随机结果。
- 所有核心人物有稳定ID、真实生命周期、关系和记忆；切场景与读档不重建人生。
- 长行动跨过到期事项时按序结算；同tick死亡判定优先于主体任务完成收益，不能死后发奖。
- 随机必须先通过时代、年龄、地点、演员、资源与事实条件；约定到期事项不能靠抽奖才发生。
- 内容先结构后文案，有拒绝、延期、失败、死亡/离乡和过期处理；任何关键回望都追溯事实。
- NPC有自己的目标和选择，可以拒绝玩家。重要过去不可为了新剧本改写。
- 先采用开发期AI生成候选内容，经校验和模拟后入库；游戏离线可玩。运行时AI无权直接改钱、改关系、改死亡或改历史。
- 同种子重放要求引擎、模拟、内容版本一致，并保存随机状态；不承诺跨版本天然一致。
- 保留用户未提交修改和真实存档，不强推覆盖历史。公开发布、自动合并和付费服务按已有明确授权执行。

请现在从M0-01开始，用可核验的工作结果推进；每次完成一个小任务都把代码或文档提交并push，然后记录当前状态和下一步。
