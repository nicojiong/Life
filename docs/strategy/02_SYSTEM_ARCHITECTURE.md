# 系统架构与渐进迁移合约

> 规划版本：2026-10-24。审计基线：`nicojiong/Life@2d035379f21abbc8d1d6f06d0328eb756751b993`。本文是待实现的架构合约；不代表下列模块、测试或命令已经存在。

## 1. 技术方向与现状

继续使用 Godot、GDScript、单机离线与现有皮影/版画视觉。每次开局创建一个独立世界；世界中每个人都属于同一套规则，玩家只拥有当前角色能够获得的信息与行动权限。先把北宋的一生做通，再验证第二个时代包。

当前 `village_scene.gd` 同时承担状态、绘制、寻路、行动、对话、职业、存档和结局。`project.godot` 声明 Godot 4.7，README 的 4.7.2 路径属于作者机器配置；M0 必须检测实际引擎、成功运行后锁定精确版本和匹配的导出模板，不自行降级。当前事实以[固定提交的源码](https://github.com/nicojiong/Life/tree/2d035379f21abbc8d1d6f06d0328eb756751b993)为准。

最先解决的是一致性：普通行动仅在 `months >= 6` 时跳时间，对话始终推进月份；NPC 重建会重新初始化态度；部分状态没有持久化；长行动推进期间死亡后，调用方仍可能继续发收益并写回存档。上述路径需先做复现断言，再迁移。

## 2. 模块边界与迁移顺序

| 层 | 建议模块 | 唯一职责 |
|---|---|---|
| 领域状态 | `domain/world_state.gd`、`person_state.gd`、`household_state.gd` | 人、家庭、资产、关系、任务、世界时钟的权威数据 |
| 模拟入口 | `sim/world_sim.gd`、`action_resolver.gd` | 接收命令、验证、结算，返回结构化结果 |
| 时间与随机 | `sim/simulation_clock.gd`、`rng_service.gd` | 唯一逻辑时间；相互隔离的随机流 |
| 叙事与社会 | `sim/event_scheduler.gd`、`relationship_system.gd`、`npc_planner.gd` | 事件资格、延迟后果、记忆与NPC目标 |
| 数据内容 | `content/content_registry.gd`、`content_validator.gd` | 加载时代包，校验人物、行动、事件定义 |
| 持久化 | `persistence/save_repository.gd`、`save_migrations.gd` | 存取、备份、版本迁移与故障恢复 |
| 表现 | 现有场景、UI、寻路、声音 | 渲染状态、提交命令、展示结果，不直接修改人生属性 |

表中模块路径均位于拟新增的 `scripts/` 目录下；这些模块尚未建立。

依赖顺序：**基线与测试隔离 → 状态所有权 → 时钟/命令/随机协议 → 存档版本 → 因果事件 → NPC社会 → 时代包扩展**。这些是依赖关系，可以拆成多次小提交。每次只迁出一个子系统，通过适配层连接旧场景；旧字段与新状态不得同时成为可写的真实来源。保留现有调试舞台作为回归入口，确认等价后再删除对应旧逻辑。

## 3. 唯一时钟与行动事务

使用整数逻辑分钟作为时间单位，保存 `world_tick`；年龄由出生日期和当前日期计算。模拟日期、经济和任务只依据逻辑tick。镜头、UI补间和动画按渲染帧平滑推进，模拟暂停时仍可工作；它们不能反向推进模拟或消费模拟随机流。昼夜从逻辑日期计算目标状态，再用表现时间插值。移动命令产生的路程耗时由模拟器结算一次；动画只演示移动。现实时间模式、暂停、加速与跳过都调用同一个 `advance_to()`。

任何有持续收益的劳动、学习、交谈或经营必须消耗时间、资源或有限机会。免费查看信息可以零耗时。面板需要玩家决定时暂停逻辑时间；看风景的等待也通过同一时钟推进。必须消除“短行动无限点击、零时间获得钱和技能”的路径。

命令事务按以下顺序执行：

1. 接收 `command_id / actor_id / action_id / targets / expected_revision`，检查重复提交、人物存活、位置、年龄、费用和权限。
2. 生成行动计划，记录开始成本、预计完成时刻、取消/失败规则。开始成本与完成收益分开；失败不必全额退款。
3. 按时间顺序推进到下一个边界：行动完成、约定到期、世界事件、生日或死亡。相同 tick 按明确优先级和实例 ID 排序：该主体的死亡/失效判定先于其行动完成收益；已经在更早边界完成的结算保留，死亡时刻之后不再对该主体执行普通行动奖惩。
4. 长任务经过重要事件时暂停并返回 `INTERRUPTED`，让玩家处理后再继续；已发生的时间和成本不回滚。死亡立即返回 `DEAD`，取消该人物后续行动，不再发完成收益。
5. 每个边界的状态变化、日志与队列变更作为一个一致的提交单元；完成时重新验证条件，再结算一次收益。
6. 返回 `COMPLETED / INTERRUPTED / CANCELLED / REJECTED / DEAD`，携带原因、已耗时间、状态变化、后续事件 ID。表现层不得在返回后追加收益。

M1先建立最小时间边界队列，只处理行动完成、生日、年关和死亡；M2在同一队列上扩展叙事资格、机会抽取和过期策略，不另造第二套时钟或到期队列。

多人都随世界时钟老去、消费、工作和死亡，不能依赖当前操控视角。切换父母视角只改变控制者和可见信息，不能复制资产、重置关系、重复领取年收入或复活人物。

## 4. 随机、日志与重放

随机流固定为 `world / economy / social / narrative / visual`。由世界种子和稳定命名派生，各自持有 `seed` 与当前 `state`。绘制、镜头、NPC装饰走动只用 `visual`，不能改变人生事件抽签。候选集合先按稳定 ID 排序，避免字典遍历顺序影响结果。

重放成立的范围是：**相同引擎版本、模拟版本、内容包版本/哈希、初始种子、玩家命令与已接受的AI输出**。不能只保存出生种子；存档必须保存每条随机流的当前状态。Godot 官方说明 `seed` 可产生可复现序列、`state` 可恢复状态，同时底层算法属于实现细节，因此不承诺跨引擎版本自动一致；恢复顺序是先 seed、后 state。[官方 RNG 文档](https://docs.godotengine.org/en/4.7/classes/class_randomnumbergenerator.html)

人物、家庭、地点、职业、命令、事件实例全部使用稳定 ID。一次结果至少记录：`event_id`、`tick`、`actor_ids`、`cause_ids`、`definition_id/version`、`choice_id`、`effects`、`rng_stream`、`source`。因果可以有多个父事件，例如“债务到期＋灾年减产”共同导致典当。日志只记录实际发生过的结果，墓志和回忆从日志取材，不补写不存在的经历。

## 5. 内容合约

事件定义与事件实例分离。前者是可重复使用的规则，后者绑定这一局中的具体人物。建议字段如下，均由校验器实施：

| 对象 | 必须字段 |
|---|---|
| 事件定义 | `schema_version, id, version, era_tags, actor_slots, conditions, weight, cooldown, max_occurrences, choices` |
| 选择 | `id, requirements, visible_reason, costs, duration_ticks, outcomes, followups` |
| 后续事件 | `definition_id, delay_range, inherited_bindings, expiry, invalid_target_policy` |
| 事件实例 | `schema_version, instance_id, definition_id, definition_version, role_bindings, cause_ids, opened_tick, due_tick, expiry_tick, status, resolved_choice` |

前置条件采用允许清单表达式，例如 `person_alive`、`age_between`、`has_memory`、`relationship_at_least`；效果采用 `transfer_money`、`change_relation`、`add_memory`、`schedule_event` 等有类型操作。内容包不得提供任意 GDScript、文件路径执行或 `eval`。

所有持久化字段统一使用snake_case；事件实例状态为 scheduled、available、resolved、cancelled、expired、superseded，终态不可重复结算。抽取流程为“时代/地点粗筛 → 合法演员绑定 → 精确资格与互斥检查 → 处境权重、冷却和重复修正 → 随机选择 → 提交前重验”。没有合适事件时允许平静生活。拒绝、延期、不行动必须有到期处理；NPC已死、对象离开或债务已结清时，后续事件取消或转为明确定义的替代事件，并留下原因。不能让随机生成越过世界事实。

## 6. 存档与旧版本兼容

存档包含 `save_schema_version / simulation_version / engine_version / content_manifest / world_id / world_tick / revision`，以及人物、家庭、资产、关系、记忆、正在执行的任务、事件队列、待选事件、日志和各随机流。`seed`、`state` 等64位整数以十进制字符串保存，避免JSON数值往返损失。UI布局和临时动画状态不是模拟真相。

采用“写临时文件 → 校验可读 → 备份旧档 → 替换 → 保留恢复信息”的流程，并按目标系统验证失败恢复。加载失败不能静默覆盖原档。死亡世界转入只读人生档案；开始新人生创建新 `world_id`，不删除旧人生回顾。

无版本号的现有存档视为 v0：先备份，再迁移已保存字段。过去未保存的NPC态度、母亲性情等不能凭空恢复；缺失项采用明确、稳定的迁移默认值并记录。未知的未来版本拒绝写回。M0 创建独立测试存档路径，开发测试绝不调用真实玩家目录里的清档逻辑。

## 7. 时代包与AI边界

时代包统一提供历法、出生分布、姓名、职业资格、教育制度、货币与生活成本、地图地点、人物模板、历史事件和视觉标签。内核不得写死“进士”“北宋年号”；时代包负责这些具体规则。历史模式固定大事件边界，架空模式允许有规则的偏移，两者在开局明确标注。第二时代必须通过同一套接口；添加时代不应复制一份模拟器。

AI首先用于开发期生成候选人物、事件和文案，再经 schema、引用、可达性、时代一致性、批量模拟和人工抽检入库。在线自由输入属于后期可选功能：解释成候选命令，再由规则验证。AI不可直接改金钱、职业、寿命或历史事实；离线与服务失败时回落到已验证内容。

## 8. 每次迁移的验收证据

- 相同输入在同版本产生相同结果；调整帧率、镜头和视觉随机不改变人生结果。
- 存读档前后继续执行相同命令，结果与未退出流程一致。
- 长行动遇死亡时停止，且不存在死后收入、再次行动或重复复活。
- 关系在面板重建、地图重载和父母视角切换后保持；全家年龄与唯一时钟一致。
- 长跳跃不漏过到期事件；事件重复执行被 `command_id / event_instance_id` 拦截。
- 旧档有备份和迁移报告，损坏档可恢复；所有测试使用独立数据目录。
- 新时代内容通过相同校验器；没有合适事件时仍能等待、生活和结束一生。

这些是需要 M0 起逐步建立的自动验收，现有截图和控制台打印不能代替断言。[Godot 命令行与独立脚本入口](https://docs.godotengine.org/en/4.7/tutorials/editor/command_line_tutorial.html)
