# 分阶段路线图与 Agent 任务清单

版本：规划 v1.0 · 2026-10-24。所有任务均为待实施；本规划包没有完成游戏代码任务。

## 1. 实施次序

先让现有游戏可靠，再做能够证明自由与因果的切片，随后扩充一生、社会和时代。M0–M3 是核心主线；M4 与 M5 在 M3 通过后可在独立分支推进；M6 依赖二者；M7 的可读性与性能测量可提前做，最终发布候选依赖完整验收。

| 里程碑 | 玩家/开发者得到什么 | 范围 | 出口 |
|---|---|---|---|
| M0 | 可信的起点 | 锁定真实运行基线；隔离测试；修复接线和死亡边界 | 从当前代码成功运行或明确记录环境阻断；关键缺陷有可执行复现 |
| M1 | 可靠模拟底座 | 统一人物/家庭状态、时间、命令、随机、日志和存档 | 存读档不改变世界；视角不改变结算；无零时间无限收益与死后奖励 |
| M2 | 有前因后果的童年与少年 | Storylet、到期队列、三条样例、分年龄自主权 | 从0到18岁可玩，至少两次选择产生跨年回响 |
| M3 | 第一份完整人生 | 12核心人物、3可交叉路线、约40事件、家庭与结局 | 从出生到死亡完整可玩；普通人生与拒绝路径成立 |
| M4 | 继续生活的社会 | 经济、契约、迁移、远方与自主NPC | 离开某个地点后，那里的关系和生活仍合理演化 |
| M5 | 可控的内容生产 | Agent简报、结构化生成、校验、模拟、审阅、入库 | 能稳定加入一批新内容，失败内容被阻挡且有修复反馈 |
| M6 | 真正的多时代 | 北宋EraPack、历史变化、第二时代从短切片到完整人生 | 同一内核支持两个制度不同的完整人生内容包 |
| M7 | 可交付版本 | 表现、性能、真人试玩、迁移回归、平台导出 | 形成可审阅、可回滚的候选构建与证据 |

这些是验收阶段，不是日期承诺。先用 M0 和 M1 的实际交付速度估算工期；不要把 Agent 的一次回答当成一天工时，也不要承诺有限轮次会自动完成“完美世界”。

## 2. 每轮的工作单位

一个任务有唯一 ID、单一主要结果、明确依赖、允许修改范围、验收场景和证据位置。若任务超过一次可审阅变更，拆为后缀子任务，例如 M1-04a、M1-04b，并明确迁移期间的兼容状态。不得把整个里程碑做成一个无法审查的大提交。

依赖满足的默认条件：前置任务达到ready_for_merge、精确SHA已push且包含于本任务基线；它不因被依赖而自动变为done。任务分支已 push 但尚未被后续分支引用时，并不意味着 main 已具备这些能力；新任务应明确基于哪个已验收 commit。使用堆叠分支时记录 base SHA 和集成顺序，避免从旧 main 重做已经完成的系统。

### 状态模型

todo → in_progress → implemented → validated → pushed → ready_for_merge → done。blocked 可以从未完成的任一状态进入。

- implemented：代码或内容已写，不代表测试通过。
- validated：任务要求的行为验证与审查通过，有证据。
- pushed：远端任务分支已包含指定 SHA，需确认远端，不只看本地提交。
- ready_for_merge：最新提交的要求检查通过，满足集成条件。
- done：已进入约定集成分支；如项目明确以任务分支为交付终点，必须把这一例外写进项目规则。
- blocked：记录阻断事实、已完成部分、恢复方法和检查点；不能改成 done。

机器可读的完整任务和验收标准在包根目录 backlog.json；首次导入不预填任何成功记录。以下是相同任务的人类可读说明。

## 3. 全部任务卡

### M0 · 可信的起点

#### M0-01 冻结现状与修正文档

优先级：P0；依赖：无。

交付：docs/BASELINE.md；docs/GDD.md 的有效规则索引。

验收：

- 记录真实仓库HEAD、Godot --version、环境和源码/编辑器导入检查；实际游戏运行须在已证实隔离后进行，否则明确留到M0-02补测。
- 把已实现科举等过时缺口改正；新旧设计不再同时生效。
- 列出不可执行的检查及原因，不冒充通过。

#### M0-02 建立隔离的验证入口

优先级：P0；依赖：M0-01。

交付：测试专用用户目录配置；tools/verify.ps1（拟新建）；tests/ 的最小断言入口（拟新建）；.github/workflows/verify.yml（拟新建，按真实运行环境接通）。

验收：

- 所有游戏启动和stage都使用已证实的独立数据目录；记录真实启动结果且不读取/写入玩家存档。
- 导入和启动失败返回非零退出码，关键错误不被日志吞掉。
- 现有stage明确区分演示、截图与行为断言；--fresh不接触玩家存档。
- 在可用的CI环境接通同一最小验证入口；权限或运行器不可用时如实标blocked，不宣称CI完成。

#### M0-03 统一内容ID并修复已确认接线错误

优先级：P0；依赖：M0-02。

交付：内容唯一ID/引用校验；商贾出身映射修复；重复NPC ID修复。

验收：

- 商贾出生得到对应父亲行当。
- 重复lao_seng与不存在引用会被校验拒绝。
- 只改必要映射，保留合法出身分布。

#### M0-04 阻断死亡后的行动收益与普通存档

优先级：P0；依赖：M0-02。

交付：当前调用链的终止保护；死亡中断回归场景。

验收：

- 跨寿终长行动与战死特殊行动均不继续发奖。
- 死亡只触发一次，结束后的命令被拒绝。
- 行动完成与死亡同tick时，主体死亡判定先于完成收益；先前已结算部分保留。
- 如暂未建人生档案，先留可靠迁移检查点，不再静默清档又重写。

### M1 · 可靠模拟底座

#### M1-01 抽出人物、家庭和世界状态

优先级：P0；依赖：M0-03、M0-04。

交付：WorldState/PersonState/HouseholdState/RelationshipState；现有街景适配器。

验收：

- 主角父母统一person_id且死亡保留记录。
- 家庭财产与个人字段各有唯一所有者。
- 重建场景与换视角不改变关系、职业或身份。

#### M1-02 统一时钟和行动事务

优先级：P0；依赖：M1-01。

交付：SimulationClock；ActionCommand/ActionResult；所有收益入口的统一结算适配。

验收：

- 有收益的行动消耗声明时间或有限资源。
- 建立行动完成/生日/年关/死亡的最小时间边界队列；长行动分段可中断且无重复收益，M2复用该队列扩展叙事。
- 年度结算与老化不因当前POV改变；阶段边界只触发一次。

#### M1-03 可复现随机流与因果日志

优先级：P0；依赖：M1-02。

交付：RngService五类流；Fact/EventLog；重放命令记录。

验收：

- 同版本同seed同命令得到同一状态摘要。
- 调整相机/视觉随机不改变模拟结果。
- 事件有cause_ids，ID与排序规则稳定，未知因果显式标注。

#### M1-04 版本化存档、恢复和迁移

优先级：P0；依赖：M1-03。

交付：SaveEnvelope；原子保存/备份；旧版迁移fixtures。

验收：

- 家庭、关系、事件、节令、队列、时间、RNG往返一致。
- 死亡父母不补生；旧档缺失信息按迁移策略标记而不假装恢复。
- 写入中断或损坏可回退备份；RNG的64位seed/state用十进制字符串。

#### M1-05 收敛可靠模拟底座

优先级：P0；依赖：M1-04。

交付：黄金重放fixture；生命周期边界验证报告。

验收：

- 时间/收益/死亡/读档的首批回归场景全通过。
- 关键状态仅由模拟层修改，UI无直接写核心字段通道。
- 保存中断长行动后恢复不会重复扣费或发奖。

### M2 · 有前因后果的童年与少年

#### M2-01 建立事件定义与实例协议

优先级：P1；依赖：M1-05。

交付：版本化Storylet schema；条件/效果允许清单；EventInstance与role_bindings。

验收：

- 缺字段、非法效果、跨时代引用和演员冲突在入库时失败。
- 同一事件定义可以绑定不同合法人物。
- 定义与运行中的事件状态分离，无任意eval。

#### M2-02 建立到期队列与机会调度

优先级：P1；依赖：M2-01。

交付：Scheduler；候选筛选与加权选择；过期/取消/互斥策略。

验收：

- 到期债务不能因随机抽选而漏处理。
- 同tick按优先级和稳定ID排序，级联事件有上限与后续处理策略。
- 演员死亡/迁移和无候选有可解释结果，不无限循环。

#### M2-03 迁移三条因果样例

优先级：P1；依赖：M2-02。

交付：借米/偿还或延期链；家庭牺牲/珍贵物品链；拜师/介绍/拒绝链。

验收：

- 22岁以后新借款仍按实际日期到期。
- 每链有接受、拒绝、缺资源和演员失效路径。
- 所有长期后果跨存档与年份保持正确。

#### M2-04 实现分阶段自主权

优先级：P1；依赖：M2-03。

交付：AgePolicy/GuardianPolicy；0–6、6–12、12+对应行动集；个人与家庭导演模式边界。

验收：

- 0–6的家庭决定取决于家境与监护人目标。
- 6–12可以争取和拒绝部分安排；12+扩大行动空间。
- 不可行动说明理由和替代方案；无出生终身职业锁定。

#### M2-05 交付0–18岁可玩因果切片

优先级：P1；依赖：M2-04。

交付：纪事/承诺/因果反馈UI；同种子不同选择演示记录。

验收：

- 至少两个选择产生可见跨年回响。
- 玩家能看见成本、承诺和已知信息；未知事实不提前泄漏。
- 真实试玩能解释前因后果；记录尚未解决的体验问题。

### M3 · 第一份完整人生

#### M3-01 让12名核心人物拥有独立生活

优先级：P1；依赖：M2-05。

交付：NPC基础目标/需要/效用选择；稳定人物关系与记忆；原创角色模板。

验收：

- 玩家不干预时NPC会做合法行动。
- NPC会拒绝且行为可解释；同名不同ID不混淆。
- 人物死亡/迁移影响相关事件，回忆引用真实事实。

#### M3-02 打通三条可交叉的生活路线

优先级：P1；依赖：M3-01。

交付：求学路线；手艺/营生路线；留乡/照护路线。

验收：

- 三路线均能从出生玩到结局。
- 不读书、改行、晚年补学具有可达路径。
- 不同路线至少改变关系网络、机会或生活结构，不只是数值名称。

#### M3-03 替换固定婚育和家庭年龄节点

优先级：P1；依赖：M3-02。

交付：关系发展与双方意愿；家庭生命周期；父母/子女独立状态。

验收：

- 不在固定年龄强制婚育/丧亲/抱孙。
- 拒绝关系或无子女人生可继续。
- 家庭变化依据person状态与时代规则，文案演员正确。

#### M3-04 完成死亡与人生档案

优先级：P1；依赖：M3-03。

交付：只读人生档案；基于事实的多维传记/墓志；重新开始与继续世界的明确规则。

验收：

- 每个结局关键句能追溯到事实或注明叙述者评价。
- 普通生活有具体回望，不以未考进士判定无意义。
- 死后不接受活人命令；新局world_id不复用旧局状态。

#### M3-05 完成首个完整人生版本

优先级：P1；依赖：M3-04。

交付：约40条已验证storylets；3条长期回响链；实际试玩与批量模拟报告。

验收：

- 覆盖各年龄和路线，重要事件均有可达fixture。
- 固定种子集合批跑无状态不变量错误，记录样本范围而非声称零bug。
- 玩家能辨识人物愿望与自己的两次长期影响。

### M4 · 继续生活的社会

#### M4-01 让经济成为生活选择的约束

优先级：P2；依赖：M3-05。

交付：家庭/个人/经营账本；契约与物品归属；可解释的收入和费用。

验收：

- 转账不复制资产，抽象收入/回收有来源类型。
- 照护、教育、迁移、工具与经营有用途和机会成本。
- 缺钱时有合理行动空间，避免某出身必然早死的失衡。

#### M4-02 加入县城旅行与远方联系

优先级：P2；依赖：M4-01。

交付：地点图与旅行任务；远方信息/通信；NPC分层模拟。

验收：

- 旅行实际消耗统一时间并处理中途事件。
- 人物离开可视场景不丢ID、债务和关系。
- 返回时世界已合理变化，重要因果仍可追溯。

#### M4-03 扩展职业组织与NPC冲突

优先级：P2；依赖：M4-02。

交付：更多可组合身份；组织与共同目标；社会系统回归。

验收：

- 改行依据技能/契约/资源，不统一惩罚所有旧职业。
- 至少一个不由玩家触发的NPC冲突影响机会。
- 扩展后已有三路线与旧档保持兼容。

### M5 · 可控的内容生产

#### M5-01 建立Agent内容生产流水线

优先级：P2；依赖：M3-05。

交付：内容brief与生成模板；草稿隔离区；schema/语义/模拟/审阅入口。

验收：

- 每批先10条小规模候选验证。
- 失败内容不进入正式包，保留错误与修订记录。
- 年龄、演员、物品、时代、成本与后果检查可复现。

#### M5-02 建立质量反馈与受控扩量

优先级：P2；依赖：M5-01。

交付：内容覆盖/重复/不可达报告；来源和内容版本记录；审阅任务生成规则。

验收：

- 每条正式内容至少有可触发fixture和拒绝/失效覆盖。
- 生成模型换版不静默改变已存档世界。
- 离线无模型依然可完整游玩；运行时AI只列为独立可选实验。

### M6 · 真正的多时代

#### M6-01 把北宋迁移为完整EraPack

优先级：P2；依赖：M4-03、M5-02。

交付：EraManifest和兼容协议；北宋制度/日历/角色/内容映射；时代数据隔离。

验收：

- 加载入口不固定song.json。
- 内核不硬编码宋代称谓、货币或出生年。
- 包声明覆盖整个允许人生的年份与超界策略。

#### M6-02 接通时代变迁与出生选择

优先级：P2；依赖：M6-01。

交付：时代选择与出生流程；世界历史节点队列；历史背景/架空模式记录。

验收：

- timeline事件实际影响地方状态与机会。
- 相同大历史下不同家庭/行动仍有不同人生。
- 历史资料与玩法虚构标注清楚，年龄与历法一致。

#### M6-03 第二时代短切片验证架构

优先级：P2；依赖：M6-02。

交付：制度差异明显的第二时代试验包；跨时代同一套契约测试。

验收：

- 短切片包含出生、成长、营生和关系。
- 第二时代不出现宋代科举、货币和称谓泄漏。
- 正常增加第二时代主要修改内容与明确制度模块，不复制整个游戏。

#### M6-04 让第二时代具备完整人生

优先级：P2；依赖：M6-03。

交付：第二时代完整年龄覆盖；时代选择可玩标记；分别隔离的存档与内容版本。

验收：

- 第二时代至少三条生活方向可走完一生。
- 切换时代只发生于开局或明确的新世界操作。
- 未完成时代仍标为试验，不以短演示冒充完成。

### M7 · 可交付版本

#### M7-01 完善画面、可读性与性能

优先级：P2；依赖：M3-05。

交付：年龄/身份外观差异；文本/输入/暂停设置；性能基线和热点修复。

验收：

- 指定硬件/分辨率/种子下测量帧时间与模拟步耗时。
- 重要文本与反馈可读，快捷键/鼠标操作一致。
- 性能优化不改变固定seed的模拟事实。

#### M7-02 完成实际试玩与稳定性验收

优先级：P2；依赖：M6-04、M7-01。

交付：多路线实际试玩反馈；回归/迁移/性能报告；剩余问题分级。

验收：

- 玩家反馈与自动检查分列，不由Agent代填真人感受。
- 严重状态损坏与主路径阻断清零于规定测试集。
- 不通过的体验目标进入下一轮具体任务。

#### M7-03 交付可回滚的发布候选

优先级：P2；依赖：M7-02。

交付：实际导出配置与平台构建；变更日志/兼容说明；候选版本和回滚点。

验收：

- 在声明平台实际启动候选构建并完成冒烟。
- 可定位commit、引擎版本、内容哈希和产物。
- 公开发布/合并依据已有授权和分支规则；未获授权时保留可审阅候选。

## 4. 首次交给 Agent 的任务

第一次只执行 M0-01，并在具备环境后接续 M0-02。目标是拿到真实基线与安全的验证入口，不是新增时代、NPC 或重做美术。

开始时必须检查：

1. 远端 HEAD 是否仍是本规划引用的基线；若变化，先增量阅读并更新差异，不盲目覆盖。
2. 实际根目录和相关子目录有无 AGENTS.md；本包模板不是自动生效的系统指令。
3. 本地是否存在用户未提交改动；保留并使用独立任务分支/工作树。
4. 可用 Godot 的实际版本与项目兼容性；仓库的版本声明不等于当前环境已安装。
5. 是否有 push 权限、已有 CI、分支规则与现成任务分支；缺什么据实记录。
6. 当前玩家存档在哪里，测试会写到哪里；未证实隔离前不启动游戏或任何stage，不能只禁用 --fresh。

M0-01 的完成报告应该短而具体：当前代码能否启动、哪些功能已接入、三项最重要风险、下一张任务卡、commit/remote SHA；如果只完成审计文档，不能写成游戏修复已完成。

## 5. 扩展内容的优先顺序

首批优先复用现有“借米”“拜师”“当镯”“读书”“节令”素材，让这些事情产生持续后果。先写10条高质量候选验证生产链，再扩大到首个完整版本约40条。新增内容至少服务一个明确缺口：某年龄无事可做、某路线不可达、某人物没有自主行为、某选择没有回响。

后续内容按覆盖矩阵取样：时代 × 年龄 × 家境 × 生活方向 × 关系类型 × 情绪基调。先找缺口，不用相似文案刷数量。固定验证种子与额外探索种子分开，避免只在训练用的几条人生上表现正常。

## 6. 不作为本轮验收目标的远景

联网共享世界、开放式玩家 MOD、跨代继承、任意自由文本动作、实时语音 NPC、大规模国家政治、更多历史时代都可以进入长期候选池。它们必须在当前核心闭环通过后另建任务、成本估计和兼容方案。

完整长期计划不等于一次执行无限续跑。每轮都依据任务依赖和验收结果选择下一步，并在预算/环境耗尽时保留可恢复状态。真实用户试玩决定体验是否进步，自动测试保障规则没有被破坏。
