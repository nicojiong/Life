# 《浮生 / Life》整体游戏规划

版本：规划 v1.0 · 2026-10-24（Asia/Shanghai）  
对象：nicojiong/Life · 基线提交 2d035379f21abbc8d1d6f06d0328eb756751b993  
性质：未来设计与实施约束；除明确写为“当前”的部分，均不代表已实现。

## 1. 游戏承诺

玩家选择想生活的时代，随后随机出生在这个时代的某个家庭。从依赖照护者的婴儿，逐步成长为可以作出选择的人。时代、他人的行动、自己的选择与合理的偶然，共同形成这次人生。这个世界会记得发生过的事，即使玩家没有成为名人，这一生也值得回望。

产品定位：单机、个人世界、可重玩、具有长期因果和人物记忆的人生模拟游戏。继续以现有 Godot 二维街景作为入口，以可扩展模拟规则和可组合叙事作为核心。

### 对“上天安排职位”的实施解释

随机决定的是“出生时在社会中的位置”：家庭、地域、资源、身体条件、亲缘网络和别人对你的期待。出生时不锁定终身职业。出生事实不可抹去，社会身份与人生方向可以改变。

保留一个可选的“命运倾向”概念时，它只能影响机会权重、家庭期待和被发现的潜力，不能秘密强制所有分支归于同一职业。若以后增加“宿命挑战”模式，应单独标明规则，不覆盖自由人生默认模式。

### 六项不可退让的设计原则

1. **选择有作用**：重要选择至少改变资源、关系、可行行动、世界状态或后续机会中的一项；只换一句文案不算独立选择。
2. **随机有条件**：未知结果来自合理候选与不完整信息，不来自无视时地人物的乱抽事件。
3. **他人有自己的人生**：NPC 可以拒绝、离开、改行、履行或违背承诺，不只是等待玩家点击。
4. **过去留下痕迹**：借债、帮助、失约、离乡、死亡、物品流转都留下可追踪事实与记忆。
5. **普通道路有价值**：务农、照护、手艺、友谊、安稳生活和探索都能形成完整人生；财富和官阶不是唯一胜负尺。
6. **复杂世界仍可理解**：玩家应该能理解重要行动的成本、风险来源与拒绝原因，并在回望时看到因果线索。

## 2. 第一版边界和长线愿景

| 维度 | 第一份可验收完整版本 | 后续扩展 |
|---|---|---|
| 世界 | 北宋主题的一个村庄，现有地点复用；外部地区先以旅行节点表示 | 村—县—城市—跨区域生活网络 |
| 时代 | 北宋一个内容包，内部结构可替换 | 多时代，各有制度、资源、称谓、职业与美术 |
| 人物 | 每局随机主人公与家庭，约 12 名有生活状态的核心 NPC | 活跃、邻近、远方三个模拟层级 |
| 路线 | 求学、手艺/营生、留乡照护三条可完整生活的路线 | 商业、医术、迁居、组织、军旅等组合 |
| 剧情 | 约 40 个经过验证的事件片段、3 条长期因果链 | 数据化扩充，生成候选后审查入库 |
| 表现 | 保留纸本/皮影/版画视觉，完善反馈与人物差异 | 年龄、衣着、职业、健康、季节对应外观 |
| AI | 开发阶段辅助生成内容，游戏离线可玩 | 可选运行时对话与回忆润色，有缓存与模板回退 |

表中的数量是起步工作量建议，不是仓库当前统计，也不是为了达标而堆量。若 20 个事件已能验证所需机制，先通过机制验收；内容不足则按缺口增补。

第一阶段暂不承担联网多人、全球每个人逐帧模拟、任意自由文本直接改变世界、无预算的在线生成、三维重做。它们不是达成“独特人生”的前提。大地图和大量事件在底层可靠之后逐步扩展。

## 3. 开局：先选时代，再遇见自己

建议开局流程：选择已完成时代 → 选择人生节奏/叙事强度 → 生成世界与出生 → 看见当时能知道的信息 → 进入生活。

时代选择页面只能把通过验收的内容包显示为可玩。规划中的时代可以展示说明，但不能假装只换一个标题就已完成。

### 出生生成顺序

时代及出生年 → 地域 → 家庭结构/生计 → 家庭资源与既有社会网络 → 主人公身体与气质 → 核心人物关系 → 初始世界状态。

使用有条件的联合生成：地域会影响可能的职业、财产和交通；家庭资源会影响学习渠道，但不应决定人格好坏。避免把每个字段独立掷骰子后拼出互相矛盾的人。

每个出生包至少包含：world_id、seed、era_id/version、出生日期、birthplace_id、household_id、监护关系、资源、背景事实、可见信息、初始机会、生成版本。身份 ID 与显示名字分离。

“身份未知”指玩家开局前不指定自己的全部人生，不等于婴儿出生界面要泄漏未来职业、寿命或所有 NPC 秘密。世界保留真实状态，玩家通过观察、交流、成长逐步认识自己。行动成本和关键规则应清晰。

默认“人生随机”每次产生新起点；调试与分享使用指定 seed。复制种子不保证跨引擎/规则/内容版本完全一致，分享记录必须同时携带这些版本。可另设自定义出生模式，但与标准随机模式明确区分。

当前代码把主人公命名参数写为男性。未来人物 schema 应解除这个硬编码，将姓名、称谓、成长与时代规则做成数据；具体出生选项属于产品设置，不在代码中处处堆分支。

## 4. 一生中的控制权

以下年龄是游戏默认阶段，不是历史或现实发展规律的精确断言。时代包可调整社会规则，人物能力与监护关系也要参与判断。

| 年龄阶段 | 玩家能决定什么 | 家庭/世界如何介入 | 代表性冲突 |
|---|---|---|---|
| 0–未满2岁 | 观察、表达亲近、不适，跳过平静时段 | 照护者安排居住、营养、出行与照护 | 照护者有不同需要，家中资源有限 |
| 2–5 | 模仿、好奇、请求同行、亲近某人 | 父母依据处境回应，不必每次答应 | 想看集市，父母今日要工作 |
| 6–11 | 读书尝试、帮工、玩伴、兴趣、提出/拒绝部分安排 | 家庭财力、监护态度和距离构成限制 | 想读书却需照护家人；想学手艺却被期待读书 |
| 12–17 | 学徒、求学、较独立社交、有限旅行、积累收入 | 技能、契约、照护和时代制度持续作用 | 离乡机会与家庭责任冲突 |
| 成年 | 改行、迁居、关系、经营、组织参与、照护、冒险 | NPC 意愿、资源、制度与风险共同回应 | 稳定生计与探索新生活的取舍 |
| 老年 | 传承、修复关系、休息、授徒、整理记忆 | 身体与社会关系变化影响可行动作 | 补偿遗憾、放下或继续未竟之事 |

0–6 岁应短而有记忆点，不能长时间被动等待。首次体验可以有 3–6 个重要片段；重复游玩可以压缩日常，保留真实的出生与成长结果。

现有父母切换玩法建议保留为“家庭导演/代管”模式；默认个人人生模式中父母按自己的目标行动。两种模式使用同一套世界状态与时间，切换不会重新生成关系或复制收入。任何跨角色操作都必须保留明确 actor_id。

“不读书”应是一条可生活、可成长的道路：学习来源包括师徒、口授、观察、实践、同伴和后期补学。它也带来真实限制，例如某些职业资格不足。限制应提供解释和替代路径，不把选择变成强制失败。

## 5. 每次游玩的核心循环

观察处境 → 形成当下意图 → 查看可行行动及代价 → 作出选择或等待 → 时间与所有相关人物同步推进 → 规则结算 → 合理机会出现 → 记录事实、关系与记忆 → 重新认识自己的处境。

### 三种时间必须分清

年龄阶段按周岁划分，0–未满2岁、2–5岁、6–11岁、12–17岁互不重叠。

- **模拟时间**：年龄、债务、训练、收入、市场和事件都使用同一条权威时间线。
- **表现时间**：走路动画、镜头、光照的平滑变化；不能单独成为第二套经济结算时钟。
- **玩家等待时间**：通过快进、跳过平静期和重要事件中断来控制，不要求现实中等几十年。

默认把一次有经济/能力收益的行为定义为有真实代价的任务。短行为可以耗用少量时间、体力或次数，长任务可以分段完成。行动接口统一提交时长、成本、占用资源和可中断性。对话不应一律消耗一个月，半年工作也不应在零时间里领奖。

长期任务的时间跳跃必须先处理到期事件：有人来信、亲人需要帮助、任务参与者死亡时，按配置中断、延期或完成剩余结算。不能先跳到终点领取收益，再回头假装中间一切都发生了。

“什么都不做”也是一个明确的等待动作：世界照常推进、承诺可能逾期、NPC 继续生活；玩家可选择自动暂停的重要事件类别。重要决定弹窗默认暂停模拟，关闭后按已选策略推进。

节奏目标需通过实际试玩校准：先验证一场 30–90 分钟的浓缩人生是否成立，再做数小时的沉浸节奏。该范围是原型测试目标，不是当前实际时长或最终承诺。

## 6. 有因果的随机世界

事件的来源必须能归入五类：世界长期变化、地方状态、NPC 行动、玩家行动的后果、符合当时条件的偶然。

候选事件先通过硬条件：时代、时地、年龄/能力、演员存活、已知信息、物品存在、资源、冷却和互斥。通过后才按基础权重、经历、关系、环境与新鲜度抽取。

在概念上，事件权重可写成“基础权重 × 处境相关度 × 因果关联 × 节奏修正 × 重复衰减”。这不是要求所有数值线性相乘的最终算法；工程实现需定义零权重、上限、归一化和无候选时的行为。

### 四项约束

1. 确定到期事项走到期队列，例如债务期限；不要让它参加随机抽签而永不到期。
2. 玩家行为可以改变机会概率，不保证某种道德选择总能换来利益。
3. 事件导演只能选择合法内容和安排表现节奏，不能抹去已经承诺的后果。
4. 每个重要事件记录直接 cause_id；“为什么发生”至少能回溯到世界事实、玩家动作或 NPC 行为。偶然也要记录触发条件与所用随机流。

事件需要支持拒绝、忽略、延期、失败、演员离乡/死亡和时代改变。未完成支线可合理收束，不需要永远等玩家。更多规范见 03_CHARACTER_AND_STORY_BIBLE.md。

## 7. 世界系统如何彼此影响

| 系统 | 最小状态 | 对其他系统的作用 |
|---|---|---|
| 家庭 | 照护关系、共同资产、预算、责任、成员目标 | 决定童年机会、可负担学习、迁移条件 |
| 学习与能力 | 技能、知识、资格、实际经历 | 改变行动成功率、可选工作和信息理解 |
| 营生与经济 | 物品/库存、价格、工资、需求、债务 | 产生合作、冲突、迁居与风险；账目可核对 |
| 关系 | 亲近、信任、尊重、人情、约束、记忆 | 影响借贷、介绍、结伴、拒绝和支持 |
| 地域 | 距离、可达地点、旅行耗时、环境 | 影响接触人群、信息传播与经营机会 |
| 制度与时代 | 准入、教育、税费、组织、历史事件 | 影响机会结构，改变部分行动规则 |
| 身体与照护 | 健康状态、休息、功能限制、治疗/照护需要 | 影响生活安排和选择成本，不能只等于倒计时血条 |
| 人生回望 | 已发生事实、长期关系、承诺、作品和失去 | 形成基于真实记录的传记与结局 |

“闯江湖”先落成可执行的生活系统：旅行、结伴、投师、临时营生、地方组织、委托与风险。M4扩展县城与远方后接入；若以后要加入超现实武功或完整战斗，应作为明确题材和系统任务评估，不能用一个模糊自由文本按钮冒充已经支持所有行为。

改行的代价来自新技能学习、迁移、契约、资源投入与旧关系变化。不要简单把所有其他职业等级减一。允许一人兼有身份，例如农忙务农、农闲修器具、晚年授徒。

世界按重要程度模拟：眼前与关键人物细算，邻近群体按日/月更新，远方用聚合状态；人物进入关键关系后提高精度。所有层级转换保留 ID、事实和已知关系。具体人数和更新频率由性能测量决定。

### 经济的玩法目标

让钱能改变生活选择：付学费、承担照护、修屋、添工具、迁移、雇人、承担损失、帮助别人。账目按家庭/个人/经营实体区分；转账保持来源和去向，抽象收入与系统回收也明确标注。可做紧张但不把每个不富裕出生都快速推向无解死亡。

## 8. 人物设计与美术路线

延续现有纸张、木版/皮影、节令色调和手写式语言。先改信息可读性、年龄变化和角色辨识，再考虑高成本素材升级。不要为“更高级”就同时更换引擎、镜头、画风和所有 UI。

人物外观拆成可组合层：体型、年龄、发式、服装、职业道具、行动姿态、状态痕迹。外观配置独立于模拟 ID，改美术不破坏旧档。避免把职业、性别或财富直接等同于固定人格。

人物信息面板至少显示：你知道的身份、近期互动、关系变化的理由、当前可讨论的话题和重要承诺。未知事实保留未知，怀疑和传闻与事实区分。

关键 UI 包括：时代/开局、生活街景、当下行动、关系与家庭、事务/承诺、人生纪事、存档与人生档案。先让玩家在原有街景里操作，不另造多个互不一致的玩法入口。

建议参考可组合事件的设计方法与终身角色叙事体验；具体借鉴见参考文件。人物、对白和造型使用原创内容或来源明确的授权素材。

## 9. 多时代不是换皮

时代包必须提供：可出生年份/地区、年历、社会身份与家庭生成规则、教育和职业准入、货币与商品、出行条件、组织、命名与称谓、事件池、视觉音频映射、历史节点、寿命与健康规则、资料来源及可信度标记。

共用内核负责时间、人物、资源、关系、事件和存档。不同制度由有限且经过测试的规则模块组合；数据中不允许任意执行代码。

第一时代继续北宋。第二时代建议用制度差异明显的“当代小城”试验包，先做一个出生—成长—营生的短流程，验证教育、职业、货币和家庭规则确实可替换。它必须明确采用虚构地区/规则还是史实资料，不把玩法参数包装为历史事实。

出生时间和生命末期都应落在内容包可解释的时间覆盖内。临近已知年表结尾时应有明确延展规则，不能因年份越界便把所有年份叫成同一个年号。

默认“历史背景模式”：大历史节点作为外部条件，玩家能改变地方和个人处境。未来若加入“架空演化模式”，世界允许更大分歧，必须单独记录 mode/version；不能一边承诺史实，一边任意改变国家级历史。

## 10. 终局与重玩

死亡终止当前人物的行动，保留人生档案。不得在死亡后继续发放工作收益、生成普通对话或重新写出可正常游玩的死亡前状态。旧存档迁移要区分“缺字段”和“已死亡”。

保留现有墓志作为美学形式，扩展为多维回望：做过什么、照护过谁、得到/失去什么、信守/放弃哪些承诺、留下何种作品与关系。声望可以影响有没有公共记载，但“没有被历史记住”不等于这局人生没有价值。

回望只引用日志事实与可追溯解释。语言模型可以润色，不能补写从未发生的婚姻、孩子、和解、功绩。允许未完成、遗憾和平静。

一人一世界默认保存独立 world_id、seed 和角色。死后可查看档案、重新随机人生，或在未来版本开启家族延续模式；继承世界必须是明确选项，不偷偷把新局绑定旧局。

## 11. 产品验收问题

一次有效试玩后，玩家应能回答：

- 我出生在什么样的家庭，为什么我的早期机会与别人不同？
- 哪两次决定影响了几年后的事情？
- 至少一个 NPC 想要什么，他是否做了我没有命令他做的事？
- 我拒绝读书、结伴或某次委托后，还能如何生活？
- 我失败以后，世界是否继续给出合理的行动空间？
- 我的结局有哪些细节只属于这一次人生？

这些问题无法仅凭“自动测试全绿”回答。每个大里程碑需要实际试玩记录；技术正确性与体验质量分别验收。

## 12. 下一步实施原则

先修可靠性，再做最小因果人生，再扩完整人生，再扩社会规模和时代。按 04_ROADMAP_AND_BACKLOG.md 分阶段推进。一次任务只完成一个可观察结果，保留原有可玩入口，通过验证后提交并 push 任务分支。详细流程见 05_AGENT_DELIVERY_RUNBOOK.md。

“完美世界”是持续愿景。对 Agent 下达的是有范围、有预算、有证据和退出条件的里程碑，不能是永不停止的自我改进命令。
